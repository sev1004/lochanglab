# 벨가르딘 나메 2관 전투 시뮬레이션 구현 계획

> 최신 실행 지침: [combat-simulation-rebuild.md](./combat-simulation-rebuild.md). 아래는 기존 구현 이력이며 일부 완료 문구·보류 조건은 재검증 대상이다. 후속 구현은 최신 문서의 결정 기록과 단계별 통과 기준을 따른다.

작성: 2026-09-19. 사용자 제공 전투 모델이며 게임의 검증된 패턴 데이터라고 표시하지 않는다.

## 2026-09-21 엔진 재구성 진행 현황

- 완료: 보스 타임라인을 플레이어 루프보다 먼저 생성하도록 분리했다. 보스 패턴·기믹의 시작과 종료는 플레이어 모션, 이동, 입력 대기에 의해 밀리지 않는다.
- 완료: 24종 기본 패턴을 공격 가능·백 허용·피해 배율·허용 스킬·방향 변경을 가진 반열림 시간 구간으로 표현했다. 패턴 사이는 2~3초 백 프리딜 구간이다.
- 완료: 360줄, 320줄, 3잡 2회, 앵버의 고정 구간을 타임라인에 기록하고, 전투 종료 경계를 자른다. 360줄 종료 시에는 사이클 커서만 처음으로 되돌린다.
- 완료: 모션 종료 타격, 종료 이후 타격 차단, 동일 시드 타임라인 재현, 타임라인의 모션 독립성을 단위 테스트로 고정했다.
- 완료(초기): 위험 이벤트의 균등 난수값을 보스 타임라인에서 사전 생성하고, 플레이 수준별 확률 임계값만 플레이어 쪽에서 적용한다. 따라서 플레이어 행동이 난수 호출 순서를 바꾸지 않는다.
- 완료(초기): 경직·넘어짐·버벅임은 시전 전 타격을 취소하고, 경직 면역 스킬은 시전 중 경직만 무시한다. 기상기는 실제 사용 때부터 26초 쿨로 처리한다.
- 완료(초기): 3잡은 사용 기회별로 결정적인 20% 판정을 한 번만 수행한다. 당첨되면 1초 뒤 동일 카드를 이어서 판단하며 반복문 재진입으로 재추첨하지 않는다.
- 완료(초기): 보스 불가·피격·이동·3잡 대응·입력·쿨 대기·시전 점유 시간을 공통 시간축에서 합집합으로 집계한다. 중복 구간은 우선순위가 높은 원인 하나에만 귀속한다.
- 완료(초기): 결과 화면에서 피격·이동·3잡 대응·보스 불가 시간을 노출하고, 쿨비를 “쿨 완료 후 실제 사용 전까지의 대기시간” 기준으로 설명한다.
- 진행 중: 패턴별 프리딜/위험 구간의 세분화와 실제 현재 세팅을 사용한 쿨비·백어택률 검증. 2026-09-21 로드된 랜마몽 세팅으로 600초·100회 실행을 확인했으며, 90% 결과는 적룡필살 쿨비 78.64%, 주요 스킬 쿨비 58.65~61.97%로 관측 기준보다 낮았다.
- 2026-09-21 수정: 패턴 자체를 보스 방향 전환으로 처리하던 오류를 제거하고, 명시된 패턴 구간의 방향 버전만 다음 패턴으로 전달하도록 수정했다. 직전 패턴을 제외한 23개 후보에서 균등 추첨하며, 위험 이벤트는 프리딜 구간을 제외한 구간에만 생성한다.
- 미구현: 일반 스킬의 백 재확보 행동, 이벤트 큐 기반의 이동/상태이상 처리, 실제 현재 세팅을 이용한 동일 보스 조건의 수준별 결과 검증과 행동 변수 보정. 이 단계 전에는 90% 쿨비/상대 총딜 목표에 수치를 맞추지 않는다.

## 1. 범위와 화면

- 입력한 전투시간을 종료/처치 시점으로 간주한다. 해당 시점까지의 예상 총딜과 DPS를 계산하며 보스 HP로 처치시간을 역산하지 않는다.
- 현재 편집 중인 세팅, 도핑, 순서 방식 사이클을 실행 시 불변 스냅샷으로 고정한다. 실행 중 편집은 결과에 섞지 않고 재실행 안내를 표시한다.
- 횟수 방식은 UI와 엔진 양쪽에서 지원하지 않는다. 순서 방식 전환 안내만 하고 자동 전환하거나 사이클을 바꾸지 않는다.
- 상단: 보스명, 전투시간(분/초), 플레이 수준(100/90/85/80/70), 적룡필살 정책(준비 시 우선/다음 사이클), 실행·중지.
- 반복 횟수와 난수 시드는 고급 설정에 둔다. 반복 기본값은 Worker 성능 측정 후 결정한다.
- 결과: 총딜·DPS 평균/중앙값/P10~P90, 스킬별 사용/적중/실패 횟수·CPM·백 적중률·쿨 가동률, 손실 시간, 대표 시행 타임라인.
- 평균 타임라인처럼 오해되지 않게 대표 시행 번호와 시드를 표시한다. 추정 모델의 한계를 안내한다.
- 기존 패널 크기와 간격은 유지한다. 새 입력 그룹은 UI 너비 하네스에 등록한다.

## 2. 현재 코드와 연결 지점

- `src/app/page.tsx`: `sharedCombatSnapshot`, `buildSimulationForSnapshot`, `unifiedSimulation`, `cycle`, `cycleBuilderMode`가 현재 계산/사이클 연결 지점이다.
- `src/domain/combat/combat-engine.ts`: `calculateSingleSkillDamage`의 조건별 결과를 재사용한다.
- `src/domain/skill/glavier-skill-catalog.ts`: 최종 쿨타임 계산 경로를 재사용한다.
- 현재 `calculateCycleDamageRows`는 백/비백 평균과 입력 쿨타임 비율을 곱한다. 이 집계 결과를 새 엔진의 타격 대미지로 사용하지 않는다. 사용 횟수와 쿨 손실을 시간축에서 다시 계산하면 이중 차감되기 때문이다.
- 실전 백 판정도 입력 백 비율로 다시 곱하지 않는다. 기존 백 비율의 새 엔진 내 의미는 UI에 명시하며, 10번 앞 6초는 사용자 비율과 무관하게 50%다.
- 섬광구슬 적용/미적용, 청룡진·연가심공, 코어 효과와 치확 상한/뭉툭한 가시의 기존 계산 경로를 보존한다. 시간축에서 새로 적용한 효과를 기존 평균에 중복 적용하지 않는다.

## 3. 구현 단계

### 단계 A — 데이터 계약과 순수 입력 어댑터

신규 예정: `src/domain/simulation/types.ts`, `input-adapter.ts`, `motion-profiles.ts`.

- 장비·스킬·트포·보석·도핑·순서 사이클에서 UI와 독립적인 입력 생성.
- 스킬 ID 단위로 쿨을 공유한다. 같은 스킬 카드가 여러 번 있어도 독립 쿨처럼 처리하지 않는다.
- 시작 시 전 스킬 준비, 입력 전투시간 양수 검증, 빈 사이클/지원하지 않는 모션 데이터 검증.
- 사용자 지정 스킬과 절제에 미측정 모션이 있으면 임의로 절정 시간을 대입하지 않는다. 지원 범위를 안내하고 추가 데이터로 확장한다.
- 기준 사이클 시간: 적룡필살 제외 6.5~7.4초, 포함 8~8.8초. 사람 입력 반응 포함이므로 추가 반응 지연을 다시 더하지 않는다.
- 위 시간은 측정한 기준 구성에 대한 보정 목표다. 모든 사용자 사이클을 이 범위로 강제하지 않는다. 스킬별 동작·타격 오프셋으로 구성 길이에 맞게 합산한다.
- 영상 추정치를 정확한 행동 해제 프레임으로 취급하지 않는다. 공속 변경에 따른 보정과 고정 입력 지연을 분리한다.

### 단계 B — 보스 패턴 타임라인

신규 예정: `boss-patterns.ts`, `timeline.ts`, `random.ts`.

- 24종 중 직전 패턴을 제외한 동일 확률 추첨. 최초만 24종에서 추첨.
- 패턴 후 2~3초 백 프리딜. 메인 기믹은 예약 시각을 지나 진행 중 패턴이 종료되면 우선 진입한다.
- 시간 구간마다 타깃 가능/피해 배율/백 가능/허용 스킬/이동/위험 상태를 분리한다.
- 시드와 모델 버전으로 재현한다. 보스·실수·기타 난수 흐름을 분리하여 향후 세팅 비교에 같은 외부 조건을 제공한다.
- 백 이동은 0.5~2.99초, 최빈 2초의 삼각분포를 초기안으로 사용한다. 평균 2초라고 표시하지 않는다.

### 단계 C — 플레이어 행동·실수

신규 예정: `player-policy.ts`, `status-effects.ts`.

- 새 사이클 백 이동, 사이클 중에는 방향이 바뀌어도 계속 공격. 적룡필살만 백 이동/불가 시 보류.
- 적룡필살 준비 시 우선 정책도 진행 중 스킬을 취소하지 않는다. 사용 후 원래 커서로 복귀하고 사이클 내 동일 사용을 중복 처리하지 않는다.
- 시전 후 백이 돌아가면 적중 순간 비백 처리. 중단 후 남은 스킬 순서 유지.
- 실제 시전 중 피격/기믹으로 끊길 때 이미 발생한 타격은 보존한다. 미발생 타격 취소와 쿨 시작 규칙은 스킬별 계약으로 먼저 고정한다.
- 상태 우선순위: 넘어짐 > 경직 > 버벅임. 넘어짐 중 하위 상태 및 추가 넘어짐 중첩 없음. 경직 중 넘어짐 가능.
- 기상기는 최초 준비, 실제 사용 시부터 26초. 기상기 있을 때 넘어짐 2초, 없을 때 4~6초. 경직 0.5초, 버벅임 1초.
- 비프리딜 패턴에서 이동 기회당 버벅임과 패턴 전환 버벅임 기회를 구성한다. 패턴당 넘어짐 1회, 딜 불가 구간 포함 시 추가 1회. 비프리딜 시간을 최대 4초씩 나눠 경직 추첨(7초는 2회).
- 발생 기회당 `round(k*((100-level)/10)^1.2)/100`, k=버벅임5/경직7/넘어짐3. 매 프레임 추첨 금지.
- 수준별 확률(버벅임/경직/넘어짐): 100=0/0/0, 90=5/7/3, 85=8/11/5, 80=11/16/7, 70=19/26/11%.
- 이동·회피·상태 이상·보스 불가 시간을 구간 합집합으로 집계한다. 충돌 시 이동 완료가 지연되는지와 강제 다운 종료시간은 별도 이벤트로 처리하여 단순 합산/단순 최대값의 오류를 막는다.

### 단계 D — 이벤트 엔진과 대미지

신규 예정: `engine.ts`, `damage-adapter.ts`, `metrics.ts`.

- 이벤트: 보스 구간 전환, 쿨 준비, 이동 종료, 시전 시작, 타격, 시전 종료, 상태 진입/해제, 전투 종료.
- 정수 시간 단위와 동시각 이벤트 우선순위를 고정한다. 종료 경계 이후 타격은 집계하지 않는다.
- 실행 중에도 쿨이 흐르므로 사이클 동작시간을 쿨타임에 통째로 더하지 않는다.
- 1차는 기존 엔진의 조건별 평균 피해를 타격에 사용하고 패턴/행동을 확률화한다. 치명타 개별 추첨과 평균값을 동시에 사용하지 않는다.
- 백·비백, 타깃 불가, 50% 댐감, 스킬별 공격 허용을 타격 시점에 판정한다.
- 기존 카드의 버프 체크를 유지할지 실제 시간축 버프로 전환할지 아래 보류 항목을 먼저 결정한다.
- 쿨 가동률 = 1 - 준비됐으나 미사용한 구간의 합/전체 전투시간. 종료 당시 남은 활성 쿨은 미사용 시간으로 세지 않는다.
- CPM=실제 사용 횟수/전투 분. 준비 횟수와 사용 횟수, 적중 횟수를 구분한다.

### 단계 E — 반복 실행과 UI

신규 예정: `src/workers/combat-simulation.worker.ts`, `src/components/simulation/SimulationPanel.tsx`.

- Worker에서 반복 계산, 진행률/취소/오래된 결과 폐기. page.tsx에는 연결만 추가한다.
- 통계 요약과 대표 실행 로그를 분리하고 전체 반복 로그를 무제한 저장하지 않는다.
- MVP는 현재 세팅만 지원. 비교군 연동은 이후 단계에서 동일 시드·보스/실수 스트림으로 추가한다.

### 단계 F — 검증과 완료 기준

- 단위 테스트: 시드 재현, 연속 동일 패턴 금지, 24종 전체 도달, 분포 경계, 수준별 확률, 반복 스킬 공유 쿨.
- 타임라인: 모든 패턴 구간 길이 합, 기믹 지연/종료시간 절단, 패턴 사이 프리딜, 320줄 0/50/100% 피해 구간.
- 행동: 즉시/다음 사이클 정책, 적룡필살 보류와 비백 적중, 중단·재개, 기상기 26초 경계, 7초 위험 구간 경직 기회 2회, 겹치는 시간 이중 계산 방지.
- 회귀: 100% 실수 0회(보스 기믹 손실은 존재), 준비 대기와 활성 쿨 구분, 기존 계산 결과 불변, 도핑·뭉가·팔찌·코어 조건 중복 반영 방지.
- UI: 횟수 모드 실행 차단, 입력 검증, 실행 중 설정 변경/취소, 오류 표시, 현재 입력과 결과 스냅샷 식별.
- `npm run test`, `npm run typecheck`, `npm run check:ui`, production build. 브라우저에서 기존 2탭+시뮬레이션 탭을 1920/1440/1024/768/390px로 DOM 하네스와 실제 화면 검증.

## 4. 구현 전에 고정할 세부 계약

큰 기능 범위는 확정됐지만 아래를 조용히 임의 결정하면 결과가 달라진다. A/B 단계에서 기본안과 함께 확인한다.

1. 4번 이동 0.3초 포함 여부, 6번 3구간 순서, 12번 1초 이탈 시점.
2. 패턴 조건의 확률은 패턴당인지 공격 기회당인지(10/18번, 3잡). 위험 상태가 실제로 어느 시점에 발생하는지.
3. 중단된 스킬의 미발생 타격/쿨 처리 및 진행 커서. 절정 스탠스 변경 시간과 청룡진/연가심공 유효시간, 개별 타격 오프셋.
4. 기존 카드 버프 체크와 실제 버프 시간을 혼합하지 않을 것. 초기 버전에서 카드 조건을 유지하면 현실적 버프 만료를 재현하지 못한다는 한계를 명시할 것.
5. 영상의 공속 기준 및 사용자 사이클에 없는 적룡필살을 자동 삽입할지 여부. 미측정 스킬의 모션 출처.
