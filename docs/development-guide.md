# 창술사 DPS 시뮬레이터 개발 지침

## 1. 프로젝트 목표

로스트아크 창술사의 캐릭터 정보를 외부 API에서 조회하고, 사용자가 장비·각인·스탯·스킬·전투 조건을 조작하여 예상 DPS를 확인할 수 있는 웹 서비스를 개발한다.

초기 구현은 창술사와 핵심 전투 요소에 집중한다. 이후 다른 직업이나 세부 시스템을 추가할 수 있도록 도메인 모델과 시뮬레이션 엔진은 UI와 분리한다.

## 2. 기술 방향

- 언어: TypeScript
- 웹 프레임워크: React 기반 Next.js
- 스타일링: Tailwind CSS
- 상태 관리: Zustand
- 차트: Recharts 또는 ECharts
- 단위 테스트: Vitest
- E2E 테스트: Playwright
- 패키지 관리자: pnpm
- 배포: GitHub Actions를 통한 GitHub Pages 정적 배포

사용자는 자신의 API 키를 브라우저에 입력한다. 키는 로스트아크 API 직접 조회에만 사용하고 영구 저장하지 않는다. 캐릭터 데이터와 시뮬레이션 세팅은 IndexedDB에 저장하며 DPS 계산은 브라우저에서 수행한다.

## 3. 아키텍처 원칙

### 3.1 계층 분리

- `app`: 라우팅과 페이지 조합
- `components`: 재사용 가능한 표현 컴포넌트
- `features`: 사용자 기능 단위의 UI와 상태
- `domain`: 캐릭터·전투·스킬의 순수한 업무 규칙
- `lib`: 외부 API 클라이언트와 기술적 유틸리티
- `data`: 스킬, 트라이포드 등 버전 관리가 필요한 정적 데이터

시뮬레이션 계산 코드는 React 컴포넌트나 API 핸들러에 직접 작성하지 않는다.

### 3.2 데이터 처리

1. 외부 API 응답을 `lib/lostark-api`에서 수신한다.
2. API 응답을 내부 표준 타입으로 변환한다.
3. 도메인 모델에 검증된 데이터를 전달한다.
4. 시뮬레이션 엔진은 내부 모델만 사용한다.

외부 API의 필드명과 응답 구조가 도메인 전체로 퍼지지 않도록 한다.

### 3.3 재현 가능한 계산

시뮬레이션 결과는 다음 입력으로 동일하게 다시 계산할 수 있어야 한다.

- 캐릭터 및 세팅 데이터
- 전투 시간
- 스킬 사이클 또는 행동 규칙
- 대상 방어력 및 전투 조건
- 적용한 게임 데이터 버전
- 시뮬레이터 계산 버전

## 4. 코딩 규칙

- TypeScript의 `strict` 모드를 사용한다.
- 도메인 타입을 우선 정의하고 `any` 사용을 피한다.
- 함수와 변수는 역할이 드러나는 이름을 사용한다.
- 하나의 함수는 하나의 책임만 가진다.
- 계산식에는 단위와 적용 조건을 주석 또는 문서로 남긴다.
- 매직 넘버는 이름 있는 상수나 데이터 파일로 분리한다.
- 화면 컴포넌트에는 계산 로직을 넣지 않는다.
- 사용자가 입력한 값은 계산 전에 범위와 형식을 검증한다.

## 5. 테스트 및 검증

새 계산 규칙을 추가하거나 수정할 때는 반드시 다음을 확인한다.

- 순수 함수 단위 테스트
- 경계값 테스트: 0, 최소값, 최대값, 비정상 입력
- 기존 시뮬레이션 결과의 회귀 테스트
- 주요 사용자 흐름의 E2E 테스트
- `pnpm lint`, `pnpm test`, `pnpm build`

실제 게임 수치와 추정·가정 수치는 테스트와 문서에서 구분한다.

## 6. Git 및 CI 규칙

- 브랜치: `main`, `develop`, `feature/*`, `fix/*`
- 커밋 형식: `type(scope): message`
- 예시: `feat(simulation): add cooldown calculation`
- Pull Request에는 변경 내용, 검증 방법, 계산 결과 변화 여부를 적는다.
- GitHub Actions에서 lint, test, build를 실행한다.
- API 키나 비밀값을 저장소 또는 GitHub Actions에 등록하지 않는다.

## 7. 구현 순서

1. 내부 데이터 모델과 계산 규칙 정의
2. 외부 API 응답 변환기 구현
3. 순수 시뮬레이션 엔진 구현
4. 단위 테스트와 기준 시나리오 작성
5. 설정 편집 UI 구현
6. 결과 요약 및 차트 구현
7. GitHub Pages 정적 배포와 CI 구성

## 8. 문서화 기준

계산 규칙이 변경되면 `docs/simulation-rules.md`를 함께 수정한다. API 의존성, 패치 버전, 가정한 조건, 알려진 한계도 문서에 기록한다.
