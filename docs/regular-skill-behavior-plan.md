# 일반 스킬 판단 행동 모델 구현 계획

상태: 계획 작성. 아래 표는 미측정 초기 가정이며 구현·보정 완료값이 아니다.

## 1. 목표와 확정 범위

목적은 일반 스킬의 사용 시각이 실력별 판단 행동에 따라 달라지도록 하는 것이다. 쿨비는 준비 후 미사용 시간으로 계산하고 직접 보정하지 않는다.

- 100%: 새 판단 오류·망설임 없음. 모션·입력·기믹·스탠스·원본 순서는 유지.
- 90%: 현재 사용자 세팅에서 적룡포·유성강천·굉열파·맹룡열파 각각의 평균 쿨비 80~84%를 검증 기준으로 사용.
- 85% 주요 스킬 73% 목표는 보류. 낮은 수준의 목표 숫자는 새로 만들지 않는다.
- 100%와 90% 차이가 작으면 병목을 조사한 뒤 기준을 재검토한다. 자동으로 100% 규칙을 완화하지 않는다.
- 사용자가 제공한 90% 값 81.26~82.44%는 이미 범위 안이다. 초기값을 무조건 추가해 쿨비를 낮추는 것은 목표가 아니다.

사용자가 제안대로 진행하도록 요청한 것을 바탕으로, 현재 패턴 시작 시 그 패턴 내 공격 가능/불가 전환 시각도 공개하는 안을 적용한다. 방향 변경 정보와 동일하게 모든 수준에 공개하고 해석·판단만 다르게 한다. 다음 무작위 패턴·어글·등장 위치는 공개하지 않는다. 메인 기믹 5초 전 필살 예외는 기존 별도 정책으로 유지하며 일반 스킬에 미래 전체 일정을 제공하지 않는다.

사이클 재개는 반복 난무 시작에만 적용한다. 중단 복구는 회피·경직·넘어짐·강제 공격 불가 종료에 적용하고 단순 방향 변경은 제외한다.

## 2. 선행 정합성 확인

기존 완료 보고 대신 다음 경로를 실제로 확인한다. 오류 수정과 새 모델 효과는 별도 비교한다.

- 기본 패턴 필살 불가 시간은 고정 0.5초가 아니라 연속 불가 시간의 1/4인지 확인. 사용 가능·타격·장부 판정을 일치시킨다.
- quota의 필살 전용 뒤잡기 모든 경로가 제거됐는지 확인. 공통 이동과 혼동하지 않는다.
- 기믹 5초 전 및 360 최초 공격 구간 우선 사용 시 연가심공·예약·카드 복귀가 일치하는지 확인.
- 행동 패스가 치명 난수를 소비해 행동 흐름에 영향을 주는 경로, 피해 평가에서 카드별 시나리오를 스킬명 하나로 덮는 경로를 점검한다.
- 초기 준비 대기와 미사용 원인 장부 합계, 실제 취소 시각과 회복 시각을 확인한다.

선행 오류가 남아 있는 상태의 결과로 행동 상수를 보정하지 않는다. 관련 요구사항은 `combat-simulation-action-damage-plan.md`를 함께 따른다.

## 3. 구현 책임과 상태

`behavior-profile.ts`에는 버전과 실력별 설정을 추가하고, 순수 판단 함수는 별도 `regular-skill-decision.ts`에 둔다. `combat-simulation.ts`는 사건 발생·상태 갱신·다음 평가 시각만 연결한다. 보스 관측 정보는 `boss-timeline.ts`의 현재 발생 패턴을 기준으로 제한한다.

판단 상태는 전역 busyUntil에 합치지 않는다.

```ts
type DecisionTicket = {
  eventId: string;
  kind: "cycle-start" | "interruption-recovery" | "short-window" | "link-hesitation";
  visitId: number;
  cardId?: string;
  startedAt: number;
  readyAt: number;
  sampled: boolean;
  resolved: boolean;
};
```

사용 기회 ID는 방문 ID·원본 카드 ID·시도 번호로 구분한다. 입력 중 취소로 아직 시전하지 않았다면 같은 기회이며 재추첨하지 않는다. 실제 시전 또는 조건부 생략 뒤에만 해당 기회를 종료한다. 명시적 반복 카드의 서로 다른 ID를 보존한다.

행동 가능 시각은 서로 겹치는 제한의 최댓값으로 결정한다. 판단 종료 후 기존 입력 지연을 적용하되, 입력 도중 새로운 제한이 생기면 기존 입력 취소 규칙을 따른다. 판단시간과 실제 추가 대기시간을 구분해 기록한다.

## 4. 네 가지 행동

### A. 사이클 재개

반복 난무 전환 완료 시 한 번 생성한다. 조우·집중에는 생성하지 않는다. 확률에 따라 판단 지연이 발생하며, 첫 카드 쿨 대기 중에도 시간이 흐른다. 쿨보다 먼저 판단이 끝나면 추가 손실은 없다. 첫 카드가 준비돼 있어도 실패 시 판단 종료까지 기다린다.

판단 중 기믹이 오면 같은 방문 티켓을 보존한다. 360 복귀로 방문을 새로 시작하면 기존 티켓은 폐기하고 새 방문에 한 번 생성한다. 지연을 소급해 추가하지 않는다.

### B. 중단 후 복구

회피·경직·넘어짐·강제 공격 불가가 이어지는 구간을 하나의 중단 사건으로 묶는다. 복구 대상은 다음 미사용 일반 카드다.

- 공개된 강제 불가 종료 시각은 중단 시작 후 인지 지연을 거쳐 알 수 있다. 판단 지연은 인지 완료부터 진행해 불가 시간과 겹칠 수 있다.
- 갑작스러운 피격/회피는 실제 제한이 풀린 시점부터 복구 판단을 시작한다. 이는 초기 모델 가정으로 기록한다.
- 연속 피격으로 종료 시각이 늘면 기존 사건을 갱신한다. 판단 시간을 매 피격마다 합산하지 않는다.
- 기존 `attackResumeDecisionDelaySeconds` 분기는 새 복구 티켓으로 대체한다. 동일 사건에 구형·신형 재개 지연을 함께 적용하지 않는다.

### C. 짧은 공격 기회

현재 패턴 정보를 인지한 뒤 다음 실제 공격 불가 전환까지의 시간을 추정한다. 필수 입력·모션을 포함한 예상 타격 시각과 비교한다. 하위 수준은 확률적으로 추가 안전 여유를 요구한다. 초기 구현은 과소평가(보수적 대기)만 모델링하며 새 피격 확률을 추가하지 않는다.

패턴 공개 정보는 인지 전까지 사용할 수 없다. 인지 전에는 기존 현재 상태 반응형 판단을 유지한다. 내부 창 경계마다 새 추첨하지 않고 동일 카드·동일 공격 기회에서는 같은 추정치를 사용한다. 준비시간이 부족하면 다음 관측/보스 사건에서 재평가한다. 카드는 생략하지 않는다.

다음 공격 불가가 현재 패턴 내에 없으면 미래 무작위 패턴을 추정해 차단하지 않는다. 100%는 오차 여유가 0이며 공개된 구간 안에서 정확한 타격 가능 여부를 판단한다. 따라서 이 기능 자체의 정보 활용 효과는 100%에서도 별도로 비교한다.

### D. 연계 망설임

같은 방문의 이전 일반 스킬 모션이 종료되어 다음 일반 카드로 이어갈 때 한 번 판정한다. 방문 첫 카드에는 중복 적용하지 않는다. 피격/회피에서 복귀하는 기회에는 복구 티켓을 쓰고 망설임을 추가하지 않는다.

발생 시간은 이전 모션 종료부터 흐르며 다음 쿨 대기와 겹친다. 준비된 필살 삽입 중에도 판단 시계는 흐른다. 필살 이후 같은 카드로 돌아왔을 때 재추첨하거나 처음부터 다시 기다리지 않는다.

## 5. 제안 초기값 v1

표의 확률은 %이고 지연은 초다. 발생 여부 사건당 1회, 지연은 범위 내 균등분포를 사용한다. 실측이 아니며 목표 도달을 보장하지 않는다. 보간은 필요 없고 선택 가능한 6개 수준만 지원한다.

| 수준 | 난무 재개 발생 / 지연 | 중단 복구 발생 / 지연 | 보수적 기회판단 발생 / 추가 여유 | 연계 망설임 발생 / 지연 |
| --- | --- | --- | --- | --- |
| 100 | 0 / 0 | 0 / 0 | 0 / 0 | 0 / 0 |
| 90 | 10 / 0.15~0.35 | 100 / 0.10~0.30 | 10 / 0.10~0.25 | 3 / 0.10~0.20 |
| 85 | 20 / 0.25~0.60 | 100 / 0.15~0.45 | 20 / 0.15~0.40 | 6 / 0.15~0.30 |
| 80 | 30 / 0.40~0.90 | 100 / 0.20~0.70 | 30 / 0.25~0.60 | 10 / 0.20~0.45 |
| 70 | 45 / 0.60~1.30 | 100 / 0.30~0.90 | 45 / 0.35~0.90 | 16 / 0.30~0.65 |
| 60 | 60 / 0.80~1.70 | 100 / 0.35~1.05 | 60 / 0.50~1.20 | 22 / 0.40~0.85 |

복구 평균은 기존 재개값 0.2/0.3/0.45/0.6/0.7초를 유지해 중복 증가를 줄였다. 다른 세 항목은 90%가 이미 목표 범위라는 점을 고려해 작게 시작한다. 기본 입력 지연과 피격 확률은 바꾸지 않는다.

공격 가능 전환 정보 인지는 초기에는 기존 프로필의 인지 지연(100/90/85/80/70/60: 0/0.1/0.14/0.3/0.35/0.5초)을 사용하되 방향 인지 실패 추첨과는 별개로 한다. 위 보수적 판단 확률에 인지 실패 페널티를 또 더하지 않는다.

동일 사건의 같은 uniform 난수에 수준별 임계값과 범위를 적용한다. 실제 행동 경로가 달라지면 피격 결과나 최종 쿨비의 단조성까지 보장하지 않는다.

## 6. 필살과의 관계

일반 판단 티켓은 일반 카드의 진행을 막는다. 집중·예약·연가심공·쿨·보스 조건을 충족한 필살은 일반 판단 대기 중에도 우선 검토한다. 실제 모션·피격·강제 공격 불가는 필살도 따른다. 기존 필살 판단 실수와 N초 정책을 새 일반 모델로 덮지 않는다.

난무 지연은 집중 진입을 늦출 수 있다. 이 간접 영향은 실제 사이클의 일부로 유지한다. 필살 사용 후 미사용 일반 카드에 복귀하며 티켓 잔여 상태를 재사용한다. 공통 중단으로부터 일반 순서를 복구하는 지연과 모든 스킬이 실제로 행동 불가한 상태를 혼동하지 않는다.

## 7. 검증 순서 및 조정 기준

1. 제품 입력 manifest 확보: 실제 최종 쿨·공속·피해 시나리오·카드 ID·조우/반복·N초·코드 버전. 입력이 없으면 가상 시험임을 명시한다.
2. 선행 정합성 수정 후 100/90 기존 기준 실행. 660초, 공속130%, N7.5, 사용자 사이클. 100회 탐색, 최종 500회 이상.
3. 네 기능을 진단용 flag로 각각 켜고 끈다. flag는 개발 검증용이며 UI 옵션을 늘리지 않는다.
4. 단독 효과 확인 후 A→B→C→D 누적 비교. 순서에 따른 차이 확인을 위해 all-on/all-off와 각 기능 제거 비교도 수행한다.
5. 90%가 80~84%를 벗어나면 해당 사건 발생 수·쿨과 겹친 시간·실제 추가 대기부터 확인한다. 조정은 한 파라미터군씩 0.5/1/1.5배 민감도 시험으로 진행하고 확률은 0~1로 제한한다.
6. 보정에 사용하지 않은 회차 시드 및 600초 전투로 재검증한다. 다른 세팅에도 같은 숫자가 나와야 한다고 강제하지 않는다.

100% 대비 90% 쿨비 차이는 스킬별 %p와 짝지은 회차 차이의 95% 신뢰구간으로 보고한다. 임시 진단 기준으로 평균 차이 2%p 미만 또는 신뢰구간에 0이 포함되면 '차이가 작음/불확실'로 표시하고 공통 기믹·모션·순서 병목을 분해한다. 2%p는 사용자 목표가 아닌 보고용 초기 기준이다. 기준점 변경은 결과를 제시한 뒤 결정한다.

보고 지표: 총피해/DPS, 사용·적중·취소, 스킬별 쿨비, 백 비율, 청룡진·연가심공 적용, 필살 미사용 원인, 판단별 발생·중첩·추가 대기. 모든 스킬의 idle 시간을 더해 플레이어 전체 손실로 표시하지 않는다.

## 8. 필수 테스트

- 최초 조우/집중에는 재개 티켓 없음, 반복 난무 방문당 최대 1회.
- 판단이 쿨 전에 끝나면 추가 대기 0, 뒤에 끝나면 차이만 반영.
- 중단 연속 발생 및 기존 재개와 중복 가산 없음.
- 단순 방향 변경은 복구 사건이 아님.
- 현재 패턴 공개 전/다음 패턴 미래 정보 접근 없음.
- 짧은 창 대기 후 원본 카드 유지, 정확한 타격/불가 경계 처리.
- 일반 판단 중 준비된 필살 삽입, 복귀 후 재추첨/일반 카드 중복 없음.
- 100% 새 실패 확률 0 및 공개 정보 이용 경계 검증.
- 로그 유무·피해 설정 변경이 판단 난수나 시간에 영향 없음.
- 일반 장부 원인합=미사용, 겹친 대기시간의 합집합 검산.
- 기존 조우·예약·버프·피격·메인 기믹 회귀 유지.

## 9. 산출물과 완료 조건

기능 구현, 설정표 및 가정 문서, 전용 테스트, 제품 입력 manifest, 동일 전투 비교 보고서를 남긴다. 테스트 실패를 허용오차 확대나 삭제로 숨기지 않는다. UI 변경이 생기면 AGENTS와 UI 규칙에 따른 브라우저 검증을 추가한다. 일반 DPS·백 범위·배포는 이 계획 범위에 포함하지 않는다.

완료는 목표 숫자의 외관이 아니라 사건 기록으로 차이가 설명되는 상태다. 90% 범위 또는 실력 간 차이를 동시에 만족하지 못하면 충돌과 원인을 보고한다.

## 10. 1차 구현 기록

후속 코드 리뷰에서 일반 복구 판단의 필살 차단, 짧은 창 판단의 필살 적용, 사건을 건너뛰는 대기, 입력 경계 재시작, quota 뒤잡기 잔존 경로가 확인됐다. 아래 1차 구현 기록과 테스트 통과는 이 경로들의 정합성까지 증명하지 않는다. 수정 순서와 전용 검증은 [적룡필살 대기 경로 수정 계획](finisher-wait-path-correction-plan.md)을 따른다.

2026-09-28 기준으로 다음 항목을 코드에 연결했다.

- `behavior-profile.ts`에 사이클 재개·중단 복구·짧은 공격 기회·연계 망설임의 버전 1 초기값을 추가했다.
- `regular-skill-decision.ts`에 사건별 1회 판단과 범위 지연을 담당하는 순수 함수를 추가했다.
- 반복 난무 방문 시작에만 사이클 재개 판단을 생성하고, 방문·난수 키를 고정했다.

- 판단 난수는 `bossSeed` 기반 결정 키를 사용해 행동 루프 재진입이나 로그 활성화에 의존하지 않도록 했다.

## 11. 일반 스킬 쿨비 목표 조정 기록

| 85 | 75~80% | 난무 재개, 중단 복구, 짧은 기회 판단, 연계 망설임을 소폭 증가 |
