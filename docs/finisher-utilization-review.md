# 적룡필살 쿨비 검증 및 수정 계획

## 검증 범위

2026-09-27. 제품 코드는 수정하지 않고 현재 엔진을 실행했다. 실제 브라우저 캐릭터 입력은 확보하지 못했으며 아래 수치는 가상 입력이다.

- 명시적 구간 입력, simulationBuild=jeoljeong-non222, 조우 없음
- 난무: 청룡진→맹룡열파→반월섬
- 집중: 유성강천→적룡포→굉열파→사두룡격, 필살 별도 정의
- 일반 쿨 12초, 필살 36초, 모션 모두 1초, 피해 모두 100
- N=7.5, 660초, 수준별 500회, seed=bossSeed=1..500
- 실제 세팅의 피해·쿨비 예측이나 프로필 보정 근거로 사용하지 않는다.

| 수준 | 필살 쿨비 | 적룡포 쿨비 | 필살 사용 | 필살 준비 후 미사용 초 | 예약 누락/전투 |
|---|---:|---:|---:|---:|---:|

|85|81.57%|78.71%|15.394|121.609|2.782|

시전 기록에서 각 실제 쿨 구간을 전투 종료로 잘라 합산한 값/660과 엔진 쿨비의 최대 차이는 2.23e-16 미만이었다. 이 검증은 고정 쿨·재사용 중첩 없음 조건의 독립 검산이며 사용횟수×쿨/시간으로 집계 구현을 바꾸라는 뜻이 아니다.

## 확인한 문제

1. deterministicRoll의 단순 문자열 해시는 인접 방문에서 큰 상관을 보인다. seed=1..500, 방문 ID 1,3,...99와 다음 방문을 비교하면 18% 임계값의 주변 발생률은 17.792%/17.824%, 동시 실패율은 14.6%다. 독립 기대는 약 3.17%다. 실제 실행에서 연속 누락의 인과 기여는 수정 전후 동일 입력으로 별도 검증해야 한다.
2. 한 일반 카드 지연은 쿨 대기·입력 완료·3잡 지연보다 먼저 소모된다. 실제 시전하지 않아도 필살로 복귀할 수 있다.
3. reserveDeferred는 초기화만 되고 실제 시간은 집계되지 않는다. 예약 상태 변수 역시 분류에 연결되지 않아 원인 분석에 쓸 수 없다.
4. 일부 이동 완료 판정은 잔여 이동을 확인하지 않는다. 선제 이동도 일반 카드 쿨 대기 경로에 제한적으로 연결되어 있다. 영향 방향을 일률적으로 낮은 쿨비로 단정하지 않는다.
5. 페이지에서 계산 데이터가 없으면 쿨 10초를 대체 입력한다. 실제 현재 필살에 적용되는지는 미확인이다.
6. 기존 660초 500회 테스트에는 simulationBuild가 없어 제품의 명시적 구간 실행 경로 검증을 대체하지 못한다. 이번 실행은 해당 플래그를 포함했다.

## 수정 순서와 완료 조건

### 1. 입력과 재현 자료

- 실제 페이지의 엔진 입력을 자격증명 없이 추출: 캐릭터 식별, 공속, 카드 ID·구간·순서, 스킬별 최종 쿨, N, 수준.
- 누락/비유한 쿨은 실행 전 안내한다. 임의 10초로 계산하지 않는다.
- 변경 전 실제 입력과 진단 시드를 보존한다.

### 2. 판단 난수

- 새 판단 두 종류에 전용 이벤트 난수 함수를 사용한다. 전투 시드·방문 ID·판단 종류를 충분히 혼합하고 최종 avalanche를 적용한다.
- 기존 보스/피격 난수까지 함께 변경하지 않는다. 버전을 기록한다.
- 확률표, 재현성, 로그 독립성, 인접 방문 상관을 검증한다. 고정 시드에서 실패 연속 길이도 기록한다.

### 3. 한 카드 지연 상태

- 판단 완료, 지연 대기 카드 ID, 실제 시전 완료를 구분한다.
- 쿨/입력/피격 대기 동안 ID를 보존한다. 조건부 생략 시 다음 미사용 카드로 옮기되 재추첨하지 않는다.
- 시전 시작 시에만 1회 소모하며 시전 취소도 인정한다. 카드가 없으면 바로 기존 필살 준비 절차로 간다.
- 전용 테스트: 대기 중 패턴 변경, 입력 중 피격, 3잡, 조건부 생략, 시전 취소, 카드 소진, 조우 유지.

### 4. 미사용 시간 장부

- 시간 진행 당시 스탠스·예약 상태·보스 상태·행동을 구간으로 기록한다.
- 공격 불가→피격→난무/전환→예약 보류(정책/실수 구분)→백 금지→이동→다른 모션/순서→판단/입력 등 명시적 단일 귀속 기준을 정한다.
- 초기/종료 대기를 포함하고 쿨 진행 중 시간은 제외한다. 원인 합계와 readyIdleSeconds가 일치해야 한다.
- 필살 사용 기록은 현재 일반 카드 ID를 빌리지 않고 별도 정의 ID 및 집중 방문 ID를 기록한다.

### 5. 이동 및 우선 실행

- 완료는 잔여 거리/시간이 0이고 목표 방향이 유효할 때만 인정한다.
- 합의된 이동 허용 구간에서 쿨 대기·전환과 준비를 병행한다. 일반 모션·카드 순서는 유지한다.
- 예약 필살 준비 사건에서 재판단하고, 이미 끝낸 준비를 다시 부과하지 않는다.
- 구간 분할 불변성, 이동 중 방향 변경/피격, 정확한 경계 완료를 전용 검증한다.

### 6. 실제 비교

- 각 단계 후 전용/회귀 테스트, 마지막으로 실제 입력 660초·수준별 500회 비교.
- 동일 시드의 변경 전후 비교와 일반 무작위 배치를 구분한다.
- 사용/취소/적중·쿨비·총피해, 사용당 준비 후 대기, 원인별 누적 대기, 예약 누락 연속 길이 및 발생률을 보고한다.
- 100/90에는 신규 판단 실수가 0이어야 한다. 85 이하에서의 역전은 행동 기록으로 설명한다.
- N 변경, 피해/쿨비 직접 보정, 실력 상수 조정은 이번 정확성 수정에 포함하지 않는다.

## 남은 검증

실제 로드된 캐릭터 입력, 실제 입력의 최종 쿨 대체값 여부, 위 오류들의 개별 인과 기여는 미확인이다. 현재 결과만으로 실제 세팅에서 주원인을 확정하지 않는다.

## 1차 수정 결과 (2026-09-27)

- 판단 이벤트용 결정론적 난수에 avalanche 혼합을 추가해 방문 ID 인접 상관을 줄였다.
- 실제 사이클 카드의 최종 쿨타임·시나리오 데이터가 없으면 실행을 차단하도록 페이지 검사를 추가했다.
- 쿨타임 누락 시 임의 10초를 넣던 경로를 제거했다.
- `npm run typecheck`와 전체 단위 테스트 105개 통과.
- 대기 원인 장부의 실제 시간 구간화, 이동 완료 판정 통일, 실제 세팅 660초·500회 검증은 다음 단계다.

## 2차 수정 결과 (2026-09-27)

- 집중 방문별 예약 상태 구간을 기록하고, 준비 후 미사용 시간 중 예약 보류·판단 누락 구간을 `reserveDeferred`로 분리했다.
- 뒤잡기·패턴 사이 이동은 활성 이동이 실제로 종료된 경우에만 백 도달로 기록한다.
- TypeScript와 전체 단위 테스트 105개가 통과했다.
- 실제 캐릭터 세팅의 660초·500회 결과와 원인별 대기 검증은 아직 남아 있다.
