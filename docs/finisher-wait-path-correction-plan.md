# 적룡필살 불필요 대기 경로 수정 계획

상태: 1차 수정 완료. 목적은 합의한 사용 조건을 충족한 필살이 일반 스킬 판단 또는 내부 구간 경계 때문에 늦어지는 오류를 수정하는 것이다. 쿨비 상승폭은 보장하지 않는다.

## 1. 범위와 보존 조건

- `AGENTS.md`, `regular-skill-behavior-plan.md`, `combat-simulation-action-damage-plan.md`와 실제 코드를 대조한다. 기존 변경을 보존한다.
- 예약 N초, 연가심공, 조우 위치, 반복 카드 순서, 시전 모션, 입력 지연, 실수 확률, 백어택 범위를 유지한다.
- 특히 100/90%의 필살 예약 누락·준비 확인 지연 확률 0%를 유지한다.
- 진행 중 모션·피격·실제 행동 제한을 무시하지 않는다. 일반 카드 판단 대기만 필살과 분리한다.
- 일반 DPS·실력 상수 보정·UI 재설계·배포는 포함하지 않는다.
- 기본 패턴 불가 시간 1/4 정정은 별도 기존 과제다. 이번 전후 비교에 몰래 섞지 않는다. 관련 오류가 재현 테스트를 막으면 별도 변경과 비교로 기록한다.

## 2. 확인된 코드 경로

대상은 `src/domain/simulation/combat-simulation.ts`의 제품용 `runCombatSimulationInternal`이다. 줄 번호 대신 아래 구문으로 위치를 찾는다.

| 경로 | 문제 | 수정 |
| --- | --- | --- |
| `Math.max(now, controlUntil, castUntil, stanceSwitchUntil, cycleResumeUntil, recoveryReadyAt)` | 일반 복구 판단을 전체 행동 제한으로 적용 | 물리 제한과 일반 카드 판단을 분리하고 필살 후보를 먼저 평가 |
| `resolvedShortWindows`, `predictedImpact` | 필살도 일반 보수 판단 대상이며 단순 window.end를 종료로 사용 | 일반 카드 전용, 인지한 현재 패턴의 실제 공격 불가 전환으로 제한 |
| 망설임의 `now += delay`, 짧은 창의 `now = window.end` | 도중 필살 쿨 완료와 피격 등을 건너뜀 | 대기 티켓을 보존하고 다음 사건에서 재평가 |
| `now + inputDelay >= window.end` | 의미 없는 구간 분할에서도 입력을 다시 시작 | 입력 진행 상태를 보존하고 경계 사건만 처리 |
| 공격 불가 중 `drawRepositionDuration("finisher-reposition")` | quota 제외 조건 누락 | quota에서 필살 전용 뒤잡기를 생성하지 않음 |

일반 카드 쿨 대기 중 필살 쿨 완료를 확인하는 기존 분기는 이미 존재한다. 이 처리를 공통 대기 처리에 연결하되 중복 우선순위 분기를 추가하지 않는다.

## 3. A — 수정 전 기준과 실패 재현

1. 현재 diff와 관련 파일 사본/해시, 실행 입력과 시드 목록을 확보한다. 사본에 인증정보를 포함하지 않는다.
2. 제품과 동일한 명시적 조우·반복 카드 입력으로 작은 고정 타임라인을 만든다.
3. 복구 대기 중 준비된 필살, 대기 도중 준비되는 필살, 방향만 바뀌는 입력 경계, quota 전용 뒤잡기를 각각 재현한다.
4. 실패를 확인한 뒤 수정한다. 기존 테스트 결과만으로 새 경로의 정상 여부를 판단하지 않는다.

실제 입력을 확보하지 못하면 고정 가상 입력 검증은 계속하되 실제 캐릭터 검증으로 표시하지 않는다.

## 4. B — 일반 판단과 필살 준비 분리

`regular-skill-decision.ts`의 DecisionTicket을 실제로 사용하거나 동일 책임의 상태를 구현한다.

필수 상태: 사건 ID, 방문 ID, 원본 카드 ID, 판단 종류, 시작/완료 시각, 추첨 결과, 해소 여부. 키는 배열 인덱스보다 원본 카드 ID를 사용한다. 필살 삽입 후에도 같은 일반 카드 티켓을 유지한다.

판단 순서:

1. 현재 시각의 보스·피격·모션·전환 상태를 반영한다.
2. 실제 행동 제한이 있으면 다음 사건까지 진행한다.
3. 집중·예약·연가심공·쿨·스킬별 보스 제약과 기존 기믹 우선 규칙으로 필살 후보를 평가한다.
4. 기존 필살 한 스킬 지연 정책까지 반영해 필살을 선택하거나 일반 카드로 진행한다.
5. 일반 카드를 선택했을 때만 일반 복구·연계·재개 판단을 적용한다.

난무 지연 때문에 집중 진입이 늦어지는 간접 영향은 유지한다. 난무에서 필살을 시전하거나 연가심공을 새로 지급하지 않는다. 연속 상태이상은 하나의 복구 사건으로 묶고 종료가 늘어나면 기존 샘플 지연을 재사용한다. 이때 실제 피격 제한과 판단 지연을 합산하지 않는다.

예: 피격 제한이 10초에 끝나고 일반 복구 판단은 10.3초까지 남았으며 필살이 준비됐다면, 필살 입력은 10초부터 시작할 수 있다. 일반 카드는 10.3초 전에는 재개하지 않는다.

## 5. C — 대기를 사건 단위로 진행

판단 대기 중 다음 시각의 최솟값에서 재평가한다.

- 대기 티켓 완료
- 예약 필살 쿨 완료(이미 준비된 시각을 다시 선택하지 않음)
- 보스 상태 변경, 실제 피격 사건, 행동 제한 해제
- 기존 기믹 5초 전 우선 처리 구간 진입
- 전투 종료

모든 후보는 현재보다 미래인 시각만 선택한다. 현재 시각의 사건은 먼저 소비하여 무한 반복을 방지한다. 보스 실제 상태 갱신용 일정은 사용할 수 있으나 일반 행동 정책에 다음 무작위 패턴 정보를 공개하지 않는다.

예: 일반 판단 대기 20.0~20.6초, 예약 필살 준비 20.2초이면 20.2초에 필살을 재평가한다. 필살 후 일반 카드로 돌아올 때 티켓이 이미 끝났다면 추가 지연 0초다.

짧은 창에서 일반 공격을 포기해도 필살을 포기한 것으로 처리하지 않는다. 원본 커서를 진행하지 않으며 같은 카드/공격 기회의 추첨값을 재사용한다.

## 6. D — 공격 기회와 입력 경계 수정

### 공격 기회

- 일반 짧은 창 판단에서 `skill.isDragonFinisher`를 제외한다.
- 현재 패턴 인지 완료 후, 해당 일반 스킬의 공격 가능 상태가 실제로 불가로 전환하는 시각을 구한다. 허용 스킬 제한도 반영한다.
- 방향·피해 배율·freeDamage만 바뀌는 내부 분할은 공격 창 종료가 아니다.
- 현재 패턴 내 종료가 공개되지 않았다면 다음 무작위 패턴의 끝을 사용하지 않는다.
- 같은 카드/공격 기회의 안전 여유 샘플을 저장한다. 판정 완료 Set만 저장해 다음 반복에서 대기 결정이 사라지게 하지 않는다.

### 입력

입력 대기 상태에 선택 카드/필살, 시작 시각, 완료 시각, 사용 기회 ID를 보존한다. 방향 변경이나 동일 공격 가능 상태의 내부 경계를 지나도 입력을 재시작하지 않는다.

- 입력 완료 시 현재 스탠스·예약·연가심공·쿨·행동 제한·스킬 사용 가능 여부를 다시 확인한다.
- 실제 공격 불가나 피격으로 입력이 무효화되면 기존 취소 규칙을 적용한다. 아직 시전하지 않았으므로 카드·쿨·연가심공을 소모하지 않는다.
- 일반 입력 도중 예약 필살이 준비되면 아직 시전 전인 일반 입력을 종료하고 필살을 우선 검토한다. 필살 입력은 별도로 적용하며 일반 입력 진행분을 필살에 넘기지 않는다. 일반 판단 티켓과 카드 커서는 보존한다.
- 동일 시각에는 보스 변경 → 예정 타격 → 피격 → 행동 완료/다음 판단 순서를 유지한다. 입력 완료와 필살 준비가 같으면 시전 시작 전 선택에서 필살을 검토한다.
- 패턴 변경 입력 지연은 실제 패턴 방문 변경 기준이다. 이미 시작된 입력에 내부 구간마다 추가하지 않는다.

예: 입력 30.0~30.2초 중 30.1초에 방향만 바뀌면 시전 시작은 30.2초다. 30.1초부터 0.2초를 다시 기다리지 않는다.

## 7. E — quota 뒤잡기와 장부

- quota에서 생성되는 모든 `finisher-reposition` 경로를 조사하고 차단한다. 공격 불가 중 선제 이동도 포함한다.
- 패턴 사이 공통 이동·회피·추적은 이번 수정으로 제거하지 않는다. 해당 이동의 동시 시전 허용을 새로 가정하지 않는다.
- 물리 백어택 모드의 기존 뒤잡기는 유지한다.
- 일반 판단 티켓의 존재만으로 필살 미사용 전체 구간을 판단 손실로 기록하지 않는다. 당시 실제 필살 차단 원인을 사용한다.
- 일반 판단이 쿨 대기/필살 모션과 겹친 시간, 실제 추가 대기, 필살 우선 재평가 횟수를 구분해 기록한다.
- 준비 후 미사용 장부를 시전 시작 기록으로 독립 재계산한다. 원인 합계는 총 미사용 시간과 일치해야 한다.

## 8. 필수 테스트와 통과 조건

| 시험 | 기대 결과 |
| --- | --- |
| 일반 복구 10~10.3초, 준비된 필살 | 필살 입력 10초 시작, 일반 복구는 남음 |
| 일반 판단 20~20.6초, 필살 준비 20.2초 | 20.2초 재평가, 입력 후 사용 |
| 필살 사용 후 같은 일반 카드 복귀 | 카드 누락/중복/판단 재추첨 없음 |
| 일반 짧은 창 보수 판단 확률 100%인 fixture | 필살에는 해당 판단 미적용 |
| 공격 가능 구간을 방향 경계로 분할 | 물리 백 조건과 무관한 quota 시전 시간 유지 |
| 입력 중 실제 피격/공격 불가 | 미시전 카드·쿨 유지, 무효 입력 후 재평가 |
| 일반 입력 도중 필살 준비 | 필살 별도 입력, 일반 카드 보존 |
| 예약 보류/연가 소모/난무 상태 | 대기 우회로 불법 필살 사용 없음 |
| 한 스킬 지연 정책 fixture | 실제 일반 시전 1회 필요, 조건부 생략은 미인정 |
| quota + 공격 불가 + 비백 위치 | 필살 전용 이동 0회, 공통 이동 유지 |
| 로그 on/off, 같은 시드 | 행동 기록과 수치 동일 |
| 기믹·전투 종료 경계 | 시간 역행·초과 시전·피해 없음, 고정 일정 유지 |

테스트 전용 확률/타임라인 주입은 제품 상수를 변경하지 않는다. `npm run typecheck`, 관련 전용 테스트, 기존 시뮬레이션 및 기믹 우선 테스트를 실행한다. UI가 변경될 때만 UI 지침에 따른 검사와 브라우저 검증을 추가한다.

## 9. 동일 전투 전후 비교

실제 제품 입력을 보존하고 660초·공속130%·예약7.5초·100/90/85%로 각 500회 비교한다. 같은 보스 일정·시드 목록을 사용한다. 각 변경 단독 및 전체 수정 후 결과를 구분한다.

보고: 필살 사용/적중/취소, 쿨비, 준비 후 미사용 총합·원인별 시간, 제거한 대기 사례, 일반 스킬 쿨비, 전체 피해. 백어택·치명타 난수에 의해 행동이 달라지는 경우 비교 한계와 선행 오류로 명시한다.

660초에서 미사용 6.6초 감소는 쿨비 1%p 상승이다. 하지만 앞당겨진 사용은 다음 쿨·기믹 정렬도 바꾸므로 지역 대기 감소를 그대로 전체 상승 예상치로 사용하지 않는다. 실제 개선이 작거나 없으면 그대로 보고한다.

## 10. 완료 보고

단계 A→B→C→D→E 순서로 구현하고 핵심 테스트 통과 후 진행한다. 기존 기대값·허용오차를 낮추지 않는다. 수정 전 입력·실패 사례, 변경 파일, 검증 결과, 실제 입력 확보 여부, 전후 비교와 남은 문제를 문서에 기록한다. 수치 보정 없이 기록으로 대기 제거가 설명되는 것을 완료 기준으로 한다.

## 11. 1차 수정 결과

2026-09-28 기준 변경 사항:

- 물리적 상태 제한과 일반 카드 복구 판단을 분리해 복구 판단 종료 시각이 예약 필살 후보를 막지 않도록 했다.
- 짧은 공격 기회 보수 판단은 일반 스킬에만 적용하도록 했다.
- quota 모델에서 필살 전용 뒤잡기 이동이 생성되지 않도록 했다. 공통 패턴 이동은 유지했다.
- 내부 공격 가능 구간에서 입력이 끝난 뒤 `window.end`를 다시 일반 패턴 입력 지연으로 사용하지 않도록 해당 사용 기회를 종료 처리했다.
- 페이지 기본값과 실행 fallback을 전투시간 700초, 필살 예약 8초, 반복 300회로 변경했다.

검증:

- `npm run typecheck`: 통과
- `npm run check:ui`: 통과
- 시뮬레이션·필살 우선 회귀 테스트 59개: 통과
- 브라우저에서 로드된 캐릭터의 사이클 화면은 확인했다. 인앱 브라우저에서 시뮬레이션 하위 탭 클릭이 상태를 전환하지 않아 새 기본 입력값의 화면 DOM 값은 확인하지 못했다. 소스의 상태 초기값과 실행 fallback은 확인했다.
