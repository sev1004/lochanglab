## 1. 확정 범위와 금지 사항

| 실력 | 적룡필살 | 적룡포 | 일반 백어택 스킬 |
|---|---|---|---|
| 100 | 100~100% | 100~100% | 100~100% |
| 90 | 95~100% | 92~100% | 88~100% |
| 85 | 87~95% | 82~90% | 76~88% |
| 80 | 80~89% | 77~85% | 70~80% |
| 70 | 76~82% | 72~78% | 67~75% |
| 60 | 70~78% | 70~75% | 65~70% |

- 이 여섯 수준만 지원한다. 중간값 보간·임의 반올림은 하지 않는다.
- 회차별, **스킬별** 전체 적중을 모아 성공 횟수를 추첨한다. 일반 스킬 전체를 한 묶음으로 추첨하지 않는다.
- 같은 스킬의 조우·반복·중복 카드 적중은 하나의 스킬 집계에 포함하되, 피해 계산에는 해당 카드와 시전의 조건을 유지한다.
- 취소·미적중·종료 이후 타격은 대상이 아니다. 다단히트는 현재 합산 타격 이벤트 한 개를 적중 1회로 센다.
- 320줄의 피해 0 정상 적중도 포함한다. 360·320 강제 백 예외는 제거한다.
- 범위 내 정수 성공 횟수 중 동일 확률로 선택한다. 선택 횟수만큼 적중 이벤트를 편향 없이 무작위 배정한다.
- 정수 후보가 없으면 지정 범위에 가장 가까운 성공 횟수를 사용한다. 거리가 같으면 동일 확률 선택한다.
- 적중 0회면 추첨하지 않고 백어택률은 미정 값(null 등), UI는 `적중 없음`으로 표시한다.
- 백어택 속성이 없는 스킬은 백어택 미대상이다. 청룡진 등을 이름만으로 일반 백어택 그룹에 넣지 않는다.
- 피해는 개별 타격의 백/비백·치명/비치명·청룡진·연가심공·보스 배율로 기존 계산 엔진의 조건부 결과를 사용한다.
- 기대 피해 혼합, 백어택 피해 일괄 비례 조정, 목표 쿨비·총딜로 결과 덮어쓰기는 금지한다.
- 백 판정을 배정하는 후처리는 사용 시각·횟수·쿨비를 바꾸면 안 된다. 다만 아래의 기존 백 대기 제거는 행동 정책 변경이므로 기존 버전 대비 시간 결과가 달라질 수 있다. 이 둘을 구분해 검증한다.
- 일반 DPS/횟수 모드, API 키, 배포, 행동 상수 보정, 순서 편집 재설계는 범위 밖이다.

## 3. 목표 처리 구조

```text
현재 세팅의 조건부 피해 시나리오 + 명시적 사이클
                    ↓
행동 실행: 기믹·이동·입력·스탠스·쿨·시전·취소·적중
                    ↓
회차별 내부 타격 기록 (버프·시나리오·보스 상태 스냅샷)
                    ↓
스킬별 적중 N → 성공 횟수 K 추첨 → K개 이벤트 무작위 백 배정
                    ↓
배정된 백/비백 시나리오의 치확으로 치명 판정 → 실제 피해
                    ↓
스킬·기믹·전체 결과·진단 로그를 동일 기록에서 집계
```

권장 책임 분리(실제 타입명은 프로젝트에 맞춰도 된다):

- `back-attack-profile.ts`: 여섯 수준 표, 정수 후보/가까운 후보, 비율 정책 버전.
- `simulation-hit-resolution.ts`: 적중 분류, 균등 부분집합 배정, 치명/피해 계산.
- `combat-simulation.ts`: 행동·시간 진행, 내부 기록 생성, 위 함수 호출 및 배치 연결.
- 가능하면 페이지의 시나리오 선택 어댑터를 도메인 순수 함수로 추출해 단위 테스트 가능하게 한다. 계산 엔진의 공식을 별도로 복제하지 않는다.

## 4. 정수 성공 횟수 알고리즘

실력 표는 정수 퍼센트 L/U로 보관한다. N은 한 스킬의 이번 회차 정상 적중 수다.

```text
N = 0: 후보 없음, 추첨 없음, 비율 null
Kmin = ceil(N * L / 100)
Kmax = floor(N * U / 100)

Kmin <= Kmax:
  Kmin..Kmax 모든 정수 중 균등 선택
그 외:
  0..N 각 K의 d(K) = max(N*L - 100*K, 0, 100*K - N*U)
  d(K)가 최소인 후보 중 균등 선택
```

정수 비교로 95% 경계의 부동소수점 오차를 피한다. 입력 N의 유효 정수·안전한 범위 검사를 둔다.
후보가 1개이면 확정한다. 부분집합은 Fisher–Yates 등 균등 알고리즘으로 선택하고 `sort(() => random()-0.5)`는 쓰지 않는다.
범위부터 실수 비율을 추첨하고 반올림하는 방식은 **정수 후보 균등 선택과 다르므로 금지**한다.

손계산 필수 사례:

| 실력/스킬 | N | 가능한 K |
|---|---:|---|
| 90 필살 | 20 | 19, 20 각 1/2 |
| 90 필살 | 21 | 20, 21 각 1/2 |
| 90 필살 | 17 | 17 |
| 85 필살 | 3 | 범위 내 없음 → 3 |
| 85 일반 | 20 | 16, 17 각 1/2 |
| 100 백어택 스킬 | 임의 N>0 | N |
| 임의 수준 | 0 | 없음 |
| 알고리즘 가상 범위 40~60 | 1 | 0, 1 동률 → 각 1/2 |

기믹의 0피해 타격도 배정 대상이다. 고피해/버프/기믹 여부를 보고 비백을 유리하게 배치하지 않는다.

## 5. 반드시 보존할 타격 데이터

내부 `HitEvent`/`CastEvent`는 `recordActions=false`여도 계산에 필요하다. 공개 로그와 별개로 관리한다.

- 안정적인 event ID, skill ID/정규화된 스킬 키, 회차 ID.
- 카드 ID와 구간, 방문 ID, 조우 카드/일반 반복 카드/예약 삽입 필살의 출처.
- 시전 시작·타격 시각, 취소 여부/사유, 적중 여부/미적중 사유.
- 시전 시 실제 소모한 연가심공 상태(소모 후 전역 상태를 읽지 않음).
- 타격 시 청룡진 적용 여부(시작+6초 정확 경계 포함).
- 해당 시전의 백/비백 두 시나리오: 비치명 피해·치명 피해·치확. 카드별 정의를 보존한다.
- 타격 당시 보스 피해 배율, 기믹 segment ID, 필요 시 공개 진단 출처.
- 후속 확정값: 백어택 여부, 치명 여부, 최종 피해.

기존 actions에는 버프 스냅샷·피해 데이터가 부족하므로 그것만으로 전투를 사후 재구성하지 않는다. 전투 종료 시점의 버프/세팅으로 재계산하지 않는다.

치명 추첨은 **백 배정 이후 해당 시나리오 치확**으로 수행한다. 기존에 판정한 치명을 유지한 채 백 피해만 바꾸지 않는다.
뭉툭한 가시·섬광구슬 등은 기존 엔진의 조건부 출력 의미를 테스트로 확인한다. 이미 평균 처리된 효과를 재추첨하거나 치명 배율을 다시 곱하지 않는다. `maximumDamage`가 조건부 치명 피해인지 엔진 테스트로 확인한 뒤 그대로 사용한다.
시나리오가 필수인데 누락된 제품 입력은 이유를 안내한다. 가상 테스트용 기본 입력과 실제 제품의 완전한 시나리오 계약을 구분한다.

## 6. 난수 분리와 재현

- 보스·이동/행동·예약 실수·백 성공 횟수·백 배정·치명은 독립된 이름 공간으로 나눈다.
- 백 횟수: `runSeed + skillKey + quota-count + modelVersion`.
- 백 배정: `runSeed + skillKey + quota-allocation + modelVersion`.
- 치명: `runSeed + eventId + critical + modelVersion`.
- 카드 생성의 `crypto.randomUUID()` 등 실행마다 변하는 값만으로 난수 키를 만들지 않는다. 입력에 같은 카드가 보존되고 실행 occurrence가 안정적으로 식별되어야 한다.
- 로그 켜기/끄기와 다른 스킬의 적중 수 변화가 해당 스킬의 난수 소비 순서를 바꾸지 않는다.
- 기존 `playerRandom()` 치명 소비를 없애면 과거 seed의 이동 결과도 바뀐다. 먼저 난수 책임을 분리한 기준선을 저장하고, 그 기준선에서 백 표 변경만의 행동 불변성을 검사한다. 과거 결과와 완전 동일하다고 주장하지 않는다.
- 일반 배치는 매번 새 전투 유지. 검증에는 고정 `runSeed` 목록으로 단일 실행을 반복하는 하네스를 사용한다. 현재 배치에 seed만 넣어도 `Math.random()`을 소비하므로 재현된다고 가정하지 않는다.

## 7. 뒤잡기 비용 유지 / 백 위치 대기 제거

### 유지

- 보스 추적·회피·피격·기믹 시간.
- 현재 합의된 이동 허용 시점과 행동 프로필의 이동시간 분포/배율.
- 쿨 대기 중 선제 준비, 상태이상에 의한 이동 중단과 잔여 시간, 이동·스탠스 전환 중첩.
- 일반 모션 도중 방향이 바뀌어도 모션 취소 없이 공격 유지.

### 대체

`playerAtBack`을 시전 허용/타격 백 성공의 필수 조건으로 사용하지 않는다. 물리 위치 진단이 남더라도 최종 백 배정에는 영향을 주지 않는다.
준비 에피소드를 별도로 두어 `필요 → 진행(잔여량) → 완료 → 해당 사용에서 소비`를 기록한다.

제안 상태 항목: `episodeId`, `purpose`, `remainingSeconds`, `completedAt`, `consumedByCastId`.

- 기존 정책이 요구하는 포지셔닝 기회에서만 에피소드를 생성한다. 매 스킬마다 새 이동 비용을 만들지 않는다.
- 진행 중 내부 구간 경계·방향 인지·피격으로 같은 이동을 처음부터 재추첨하지 않는다. 이동한 시간과 잔여량을 보존한다.
- 완료된 준비는 해당 사용 전에 백 불리언이 false라는 이유로 재부과하지 않는다. 다음 별도 정책상 이동 기회에서만 새 에피소드를 생성한다.
- 필살 예약 N초, 예약 누락/한 스킬 지연, 연가심공 의무는 그대로 유지한다.
- 필살 선택은 쿨·집중 방문·예약·준비·입력·공격 가능·허용 스킬 조건으로 결정한다. 백 금지만으로 필살을 보류하지 않는다.
- 조우 필살에도 준비 비용을 적용하되 조우 카드 위치를 바꾸지 않는다.
- 준비 확인 지연 추첨은 물리적 백 여부가 아닌 실제 선택 준비 조건으로 바꾼다. 사건당 한 번, 일반 카드 실제 시전으로 한 번 소비. 취소 시전도 소비하고 생략/쿨 대기는 소비하지 않는다.
- 쿨 대기 중 완료한 준비를 쿨 완료 후 다시 더하지 않는다.

새 준비 에피소드의 정확한 생성/종료는 기존 허용 정책에서 추출한 결정표와 전용 테스트로 고정한다. 코드 조사 중 기존에 없는 추적·회피 규칙을 새로 만들거나 모든 방향 변경마다 비용을 더하는 식으로 범위를 확장하지 않는다. 새로운 게임 정책 선택이 불가피하면 해당 부분만 질문한다.

## 8. 기믹 속성 분리

`forceBackAttack` 제거 전 각 기믹 segment에 `attackable`을 명시한다.

| 기믹 구간 | 공격 가능 | 피해 배율 | 백 배정 |
|---|---|---:|---|
| 360 첫 30초 | 가능 | 1 | 일반 quota에 포함 |
| 360 나머지 30/50초 | 불가 | 0 | 적중 없으므로 제외 |
| 320 첫 30초 | 가능 | 0 | 정상 적중이면 포함 |
| 320 다음 20~30초 | 가능 | 0.5 | 포함 |
| 320 그로기 10초 | 가능 | 1 | 포함 |
| 320 마지막 5초 | 불가 | 0 | 제외 |

모든 구간 이동 가능이라는 최신 합의는 유지한다. `damageMultiplier===0`으로 공격 불가를 추론하지 않는다.
기본 패턴의 `allowedSkills`와 `attackable`은 유지한다. 예: 특정 스킬만 가능한 구간을 백 판정 통합 때문에 모든 스킬 공격 가능으로 바꾸지 않는다.
`backAllowed`는 원래 패턴 설명/진단에 남길 수 있지만, 새 모델에서 적중 여부·필살 대기·백 배정·피해를 차단하지 않는다. 모델상 통계적 백 판정임을 문서/화면에 알린다.

## 9. 집계·UI·저장

- 확정 타격 기록에서 스킬 피해·치명·백횟수·기믹 피해·전체 피해를 일관되게 합산한다.
- 사용/적중/미적중/취소 및 쿨비 장부는 행동 단계에서 계산한 사실을 유지한다.
- 백 금지 때문에 실제 대기하지 않으면 `backForbidden` 손실을 만들지 않는다. 호환용 필드는 0과 deprecated 설명을 유지하거나 UI와 함께 제거한다. 기존 미사용 시간을 임의로 지우지 않고 실제 제한으로 재분류한다.
- 회차별 정수 배정을 완료한 뒤 배치 평균을 계산한다. 평균 적중 수에 정수 배정을 적용하지 않는다.
- 배치 백어택률은 현재처럼 `전체 회차 백횟수 합 / 전체 회차 적중 합`(적중 가중 비율). 회차 비율 단순 평균과 혼동하지 않도록 명시한다.
- 후보 없음 fallback 때문에 표시 비율이 표 범위 밖일 수 있다. 범위로 clamp하지 않고 fallback 회차 수를 진단에 남긴다.
- 첫 회차 로그와 500회 평균을 명확히 구분한다. 첫 회차 로그만으로 평균 검증을 완료하지 않는다.
- 비대상 스킬은 `해당 없음`, 대상이지만 적중 0은 `적중 없음`. 전체 백 진단의 분모에서도 비대상 스킬은 제외한다.
- 공개 진단에 skillKey, N, L/U, Kmin/Kmax, 선택 K, fallback 여부, seed/모델 버전을 남긴다.
- 실력 옵션은 이미 여섯 개다. 새 옵션/보간 UI를 추가하지 않는다. 기존 크기/배치 유지, 필요한 설명과 진단만 수정한다.
- 결과 상태에 모델 버전을 포함하고 이전 모델 결과를 새 결과처럼 재사용하지 않는다. 세팅·사이클 저장 스키마는 불필요하게 변경하지 않는다.

## 10. 구현 순서와 단계별 완료 게이트

### P0 현재 동작과 입력 보존

- dirty tree와 제품 실행 경로 확인. 기존 변경 보존.
- 실제 로드 세팅을 비밀키 없이 입력 fixture로 확보하고 공속·최종 쿨·카드·N초 기록.
- 현재 단위/타입 검사를 실행하여 기존 실패와 신규 실패를 구분.
- 시나리오 결과가 행동으로 되먹임되지 않는지 조사 결과 기록.

### P1 quota 순수 함수

- 표/정수 후보/fallback/균등 부분집합/0적중/비대상 구현.
- 손계산 예제와 결정적 난수 stub로 전 후보 선택·중복 없음 검사.
- 분포 검증은 고정 seed 다수로 통계적 점검을 추가하되, 매번 흔들리는 테스트를 유일한 합격 기준으로 쓰지 않는다.

### P2 내부 이벤트와 피해 해결 단계

- 행동 RNG와 피해 RNG 분리, 타격 스냅샷 구축.
- 먼저 동일 백 마스크를 넣어 기존 조건부 피해 선택과 동등성을 검증한 뒤 quota 연결.
- 엔진 시나리오 8조합(청룡진/연가/백) × 치명/비치명, 피해배율 0/0.5/1을 검증.
- 총피해 = 이벤트 합 = 스킬 합, 기믹 피해 = 해당 segment의 이벤트 합 확인.
- 로그 on/off에서 전체 결과 동일.

### P3 행동 충돌 해소

- 포지셔닝 에피소드, 백 금지 필살 대기 제거, 한 스킬 지연 실제 시전 소비 수정.
- 카드 누락/중복 없음, N초 경계 유지, 취소 시 쿨/연가 소모 유지.
- 동일 상태 구간 분할로 이동 재추첨/결과 변화 없음.
- 새 행동 기준에서 백 범위만 바꾸면 시전/적중/미적중/쿨비/손실 구간 완전 동일.
- P2와 P3의 전후 차이를 따로 기록. 시간 결과 변화는 P3의 원인으로 설명.

### P4 기믹·결과·페이지 연결

- 기믹 공격 가능 명시화 후 강제 백 제거.
- 결과/기믹/배치/첫 회차 로그 정합성 및 0적중 표시.
- 일반 DPS·횟수 모드 회귀. 과거 물리 백 테스트는 변경된 요구를 기록하고 새 quota/기믹 테스트로 대체. 관련 없는 테스트의 기대/허용오차 변경 금지.

### P5 실제 입력 반복·브라우저 검증

- 실제 현재 세팅, 660초, N=7.5, 여섯 수준 각 500회. 각 회차 N/K 범위·fallback·피해합 검증.
- 순서/횟수 및 시뮬레이션 실제 결과 화면, 1920/1440/1024/768/390px 검사. DOM 하네스와 스크린샷을 모두 확인.
- `npm run typecheck`, `node --test tests/unit/combat-simulation.test.ts` 및 새 테스트 파일, `npm test`, `npm run check:ui` 실행. 새 테스트가 기본 스크립트 목록에서 누락되지 않도록 연결.
- UI 코드 작성 전 `docs/ui-layout-rules.md`와 관련 `node_modules/next/dist/docs/`를 읽는다. 실제 실행한 명령/폭/탭/결과만 기록한다.
- 입력 확보/브라우저가 막히면 가상 입력 결과와 구분하고 실제 검증 미완료로 보고한다.

6. 백 판정에 맞는 치확으로 치명 재판정, 평균 피해를 비치명 피해로 사용하지 않음.

9. 한 스킬 지연에서 쿨 대기/생략 미소모, 실제 시전/취소 소모.

## 12. 실제 비교와 보고

비교 표에는 실력, 입력 범위, 적중 N, 성공 K, 가중 백비율, fallback 횟수, 사용/취소/미적중, 쿨비, 준비 미사용 원인, 총피해를 포함한다.
100%는 백어택이 100%라는 뜻이며 쿨비·사용량을 100%로 강제하지 않는다. 상대 총딜 100/90/80 맞춤은 완료 조건이 아니다.

쿨감 효과 확인은 동일 회차 seed/보스 일정/사용자 정책으로 A/B를 비교한다. 회차마다 새 상황을 생성하고 비교 쌍 안에서만 조건을 공유한다. 쿨감으로 적중 수가 달라지면 quota의 정수 효과도 생기므로 추가 타격 효과와 배정 변동을 구분하여 기록한다.
우선 순수 쿨타임 변경 fixture로 시간 모델을 확인하고, 실제 장비 비교에서는 공속·피해·치확 등 함께 바뀐 조건을 명시한다. 실제 세팅의 변경 대상을 사용자가 정하지 않았다면 임의 장비 최적화는 하지 않는다.

최종 보고 구분:
- 구현 완료: 파일과 기능, 최신 합의로 대체한 규칙.
- 검증 완료: 실제 입력·명령·회차·화면·숫자와 독립 재계산 결과.
- 모델 가정: 통계적 백 배정과 별도 포지셔닝 비용, 소수 적중의 정수화 효과.
- 남은 문제: 실제 검증 실패/불가, 범위 밖 실력 보정, 아직 확인하지 못한 시나리오 피드백.

**핵심 완료 기준:** 움직임 비용은 행동으로 설명되고, 백어택은 확정 표의 정수 추첨으로 설명되며, 각 타격 피해와 전체 집계는 같은 기록으로 재현되어야 한다.

## 13. 최신 진단 분류 수정

- quota 백어택 모델에서는 실제 타격 백어택 성공률을 통계적으로 배정하므로, 준비 후 미사용 시간에 물리적인 `백 금지`를 별도 손실로 귀속하지 않는다.
- 준비 후 미사용 시간은 `강제 딜 불가`, `스탠스·순서 대기`, `예약 보류`, `뒤잡기·이동`, `상태이상`, `다른 모션`, `입력`으로 분리한다. `상태이상`은 기존의 `다른 모션`에 잘못 합산되던 시간을 분리한 것이다.
- 동일 seed·동일 보스 타임라인에서 물리 모델과 quota 모델의 행동 횟수·준비 대기 시간을 비교하는 회귀 테스트를 추가했다. 백어택 판정 방식이 시간축을 변경하지 않는지 확인한다.
