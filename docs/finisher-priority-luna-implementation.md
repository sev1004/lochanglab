# LUNA 실행 지침: 적룡필살 우선 판단과 미사용 시간 검증

> 후속 구조 계획: [행동 시간·피해 계산 분리](./combat-simulation-action-damage-plan.md). 다음 구현은 해당 문서의 A부터 진행한다. 이 문서의 예약·장부 요구사항은 보존하되, 과거 완료 보고를 새 단일 행동 실행 및 독립 피해 평가의 검증 근거로 사용하지 않는다.

작성일: 2026-09-28. 이 문서는 구현 지침이다. 아래 단계의 완료 여부는 실제 코드·전용 테스트·실행 결과로 판단한다.

## 1. 작업 목표와 경계

적룡필살이 준비된 뒤 합의한 규칙보다 늦게 사용되는 사건을 찾아 수정한다. 실제 현재 세팅으로 수정 전후 동일 전투를 비교하고, 필살과 일반 스킬의 쿨비 차이가 작은 이유를 설명한다.

진행 순서: 기준 입력 보존 → 사용 건별 진단 → 우선 판단 통합 → 미사용 장부 정정 → 동일 전투 비교.

- 이번에는 실력 상수, 예약 N초, 백어택 범위, 피해 산식을 조정하지 않는다.
- 난무에서 필살 사용, 일반 모션 강제 취소, 필수 스킬 생략, 스탠스 전환 0초 처리는 금지한다.
- 일반 DPS·편집 UI 재설계·배포는 범위 밖이다.
- 기존 변경사항을 보존한다. 단계별 핵심 테스트가 통과하면 추가 확인을 기다리지 않고 다음 단계로 진행한다.

### 이전 보고의 정정

- 직전 '필살 우선 처리 수정 완료' 작업은 엔진 수정 없이 기존 동작을 확인하는 테스트를 추가한 것이다. 쿨비 개선 증거가 아니다.
- 다른 모션 22.26초는 제거 가능한 손실의 합계가 아니다. 난무/예약 보류 중 모션 등이 섞였는지 확인해야 한다.
- 이전 600초·500회 결과는 DOM의 반올림 쿨타임을 재구성했고 모션 공속 보정·카드 조건을 완전히 복제하지 않았다. 실제 세팅 전후 비교로 사용하지 않는다.
- 기존 장부는 패턴 대응 항목을 분리했지만 정상 경로의 addIdle이 현재 입력 recordLoss보다 먼저 실행된다. 분류 정확성 수정은 아직 완료가 아니다.
- 필살 단독 fixture는 일반 목록이 비어 실행 루프가 돌지 않을 수 있다. 대상 스킬 실제 사용을 반드시 확인한다.
- 실패 테스트의 기대값을 낮춰 통과시키지 않는다. 잘못 설계된 fixture는 왜 틀렸는지 기록하고 직접 요구사항을 검증하도록 고친다.

## 3. 유지할 규칙

- 조우는 1회, 이후 사용자 반복 난무/집중 순서. 같은 스킬의 쿨 공유.
- 조우 필살은 지정 카드 위치에서 실행한다.
- 반복 집중 진입 완료 시 C <= N이면 예약 판단, C > N이면 해당 방문 보류. 같은 방문 재예약 금지.
- 예약 판단 누락과 일반 스킬 한 개 지연의 기존 확률 유지. 100/90%에서 두 확률은 0.
- 예약 필살이 준비되면 진행 중 모션을 끝내고 우선 판단한다. 일반 카드 쿨 대기는 모션이 아니므로 필살 준비 시각에 재판단한다.
- 실제 이동·입력·상태이상·공격 제한은 유지한다. quota에서는 물리 backAllowed가 필살 준비 완료를 막지 않는다.
- 필살은 연가심공과 함께 사용한다. 사용/취소 후 다음 미사용 일반 카드로 복귀한다.
- 최소 사용 조건은 전환 자격일 뿐 나머지 준비된 카드 생략 조건이 아니다. 예약 필살을 남기고 집중을 종료하지 않는다.
- 360줄 복귀, 스탠스 전환 0.3초, 청룡진 6초, 입력 공식, 피격 면역 규칙 유지.
- 보스 일정은 플레이어 행동과 독립적이다. 동시각 보스 변경 → 타격 → 피격 → 행동 판단 순서 유지.

## 4. 단계 A: 재현 가능한 기준 자료

1. 현재 작업 트리를 기준으로 엔진 의존 파일의 비교용 복사본/해시를 보존한다. HEAD만 기준으로 삼지 않는다. 복사본은 제품 번들·타입 검사에 섞이지 않게 진단용 위치에 둔다.
2. 실제 executeCombatSimulation이 사용하는 입력 객체를 확보한다. 저장된 API 응답 전체, JWT, 로컬 저장소 전체를 수집하지 않는다.
3. 기존 내보내기 경로가 없으면 개발 환경 전용 명시적 진단 내보내기를 최소 범위로 추가한다. 브라우저 접근은 사용 가능한 브라우저 스킬 지침을 따른다. 숨은 React 상태를 임의 추출하지 않는다.
4. 입력에는 카드 ID/구간/순서, 카드별 피해 시나리오, 최종 쿨, 보정 모션, 면역, N, 수준, 전투시간을 포함한다. 정밀도를 그대로 보존한다.
5. seed와 bossSeed를 회차별로 미리 생성한 manifest로 저장한다. 배치 함수가 고정 bossSeed를 모든 회차에 재사용하는지 확인한다. 비교쌍은 같은 보스 일정이고 서로 다른 회차는 서로 다른 전투여야 한다.

완료 기준: 같은 입력·manifest로 같은 결과가 재현되고, 제품 명시적 구간 경로를 실행한다. 실제 입력 미확보 시 가상 입력임을 표시한다.

## 5. 단계 B: 사용 건별 진단

선택적 diagnostics 플래그를 사용한다. 진단 활성화 여부가 난수·행동을 바꾸면 안 된다. 모든 반복의 원시 로그를 UI에 쌓지 말고 대표 회차만 보존한다.

권장 자료 구조(이름은 프로젝트에 맞춰 조정 가능):

```ts
type FinisherDecisionSnapshot = {
  at: number;
  trigger: 'focus-entry' | 'cooldown-ready' | 'motion-end' |
    'movement-end' | 'control-end' | 'boss-change' | 'before-switch';
  phase: 'encounter' | 'repeat';
  visitId: number;
  stance: '난무' | '집중';
  readyAt: number;
  reservation: string;
  nextRegularCardId?: string;
  activeMotionCardId?: string;
  activeMotionEnd?: number;
  preparationComplete: boolean;
  decision: 'cast' | 'prepare' | 'wait' | 'regular';
  reason: string;
};
```

각 필살 쿨 완료부터 다음 시전/전투 종료까지를 에피소드로 묶는다. 최초 준비는 0부터다. 쿨 완료 시각은 다음 루프의 now가 아니라 실제 readyAt을 사용한다.

에피소드별로 난무/집중 구간, 예약 결과, 모션 시작/종료, 이동 완료, 입력, 필살 시전을 연결한다. 예약 필살 로그에 현재 일반 카드 ID를 빌리지 말고 별도 필살 식별자와 방문 ID를 쓴다. 조우 필살은 원본 ID 유지.

### 다른 모션 세분화

아래를 구별하고 각각의 구간 길이를 기록한다.

1. 필살 준비 이전 시작한 모션의 잔여 부분.
2. 준비 후 시작했지만 규칙상 필요한 일반 시전: 난무, 예약 보류, 확정된 한 카드 지연 등 사유 명시.
3. 준비·예약·공격/이동 조건을 만족했는데 새로 시작한 일반 시전: 우선 판단 위반 후보.
4. 스탠스 전환: 모션과 별도 기록. 합법적 전환과 예약 필살을 남기고 이탈하는 위반 후보를 구분.

준비 후 모든 모션을 버그로 세지 않는다. 이미 시작된 모션을 취소해 얻는 가상 이득도 제시하지 않는다.

가장 빠른 합법 시전 시각은 공개된 당시 상태로 판단한다. 같은 에피소드에서 모션/상태가 바뀌면 재평가하고 입력 지연을 포함한다. 미래 보스 정보를 이용한 최적 스케줄을 정답으로 삼지 않는다.

## 6. 단계 C: 우선 판단 함수 통합

순수 판단 함수와 상태 변경을 분리한다. 판단 함수 안에서 난수를 호출하거나 카드 커서를 바꾸지 않는다.

```ts
type FinisherDecision =
  | { kind: 'none'; reason: string }
  | { kind: 'wait'; until: number; reason: string }
  | { kind: 'prepare'; reason: string }
  | { kind: 'regular-once'; cardId: string }
  | { kind: 'cast-finisher' };
```

판단 순서:

1. 조우 카드 처리인지 반복 예약인지 구분.
2. 집중/예약/쿨 완료/연가심공 기회 확인.
3. 진행 중 모션·상태이상 확인.
4. 실제 공격 가능/스킬 제한 및 준비 이동 확인.
5. 기존 사건당 한 번의 준비 확인 지연 판정 결과 확인.
6. 필살 또는 허용된 일반 카드 선택.

일반 쿨 대기 진입 전, 모든 모션·이동·피격 종료, 보스 상태 변경, 집중 이탈 직전에 같은 함수를 사용한다. 다음 대기 종료 시각은 일반 쿨·필살 쿨·보스 경계·상태 해제 등 유효한 다음 사건의 최솟값이다. now 이하 사건으로 무한 반복하지 않는다.

예약 필살이 준비됐는데 일반 카드만 쿨이면 필살 준비로 넘어간다. 모션 중에는 끊지 않고 종료 후 판단한다. 필살 삽입은 일반 커서를 증가시키지 않는다. 시전/취소 후 저장된 미사용 카드에서 재개한다.

한 카드 지연은 대상 ID를 유지하고 실제 시전 시작 때만 소모한다. 입력 피격·쿨 대기·3잡 재진입은 소모하지 않는다. 조건부 생략이면 다음 카드로 넘기고 소진 시 즉시 필살 절차로 간다. 같은 방문에서 재추첨하지 않는다.

완료 기준: 집중·예약 완료·사용 가능 상태에서 불필요한 일반 시전/집중 이탈이 없고, 규칙상 필요한 대기는 유지된다.

## 7. 단계 D: 장부 정정

권장 방식은 전투 종료 시 완성된 행동/예약/스탠스 구간과 스킬별 ready-idle 구간을 교차 계산하는 것이다. 이렇게 하면 현재 입력 기록 전에 분류하는 문제를 피할 수 있다. 비용이 크면 정렬된 경계 sweep으로 구현한다.

- 정상/취소 경로 모두 입력과 실제 시전 구간을 기록한다. 취소 모션 종료는 피격 발생 시각이며 회복 종료가 아니다.
- 모든 중첩 구간의 시작·종료에서 분할한다. 삽입 순서의 find로 원인을 선택하지 않는다.
- 단일 귀속 우선순위: 보스 공격/스킬 제한 → 피격 → 난무/전환 → 집중 예약 보류 → 물리 모델의 백 금지 → 이동 → 다른 모션 → 패턴 대응 → 입력 → 순서 대기.
- quota의 물리 백 금지 손실은 0. 합법적 포지셔닝 시간은 유지한다.
- 모션 세부 항목은 다른 모션 합계의 하위 항목이며 총시간에 중복 더하지 않는다.
- 원인 합계 = readyIdleSeconds, 쿨비 = 1-readyIdleSeconds/T.
- 초기 준비와 종료 직전 대기 포함, 쿨 진행 중/전투 종료 이후 제외.
- 고정 쿨 fixture는 시전 기록의 쿨 구간 합집합을 [0,T]로 잘라 독립 검산한다. 사용횟수×쿨/T로 대체하지 않는다.

분류만 바꾼 단계에서는 행동·타격·피해·전체 미사용 시간이 동일해야 한다. 장부 자체의 누적 오류가 발견돼 합계도 수정하면 별도 버그로 재현·설명한다.

## 8. 필수 테스트

| 사례 | 직접 증명할 기대값 |
|---|---|
| 집중 진입 시 준비된 예약 필살 | 첫 일반 카드보다 먼저 시전 |
| 일반 쿨 대기 중 필살 준비 | 일반 쿨 완료까지 기다리지 않음 |
| 일반 모션 중 필살 준비 | 진행 모션 종료+필요 입력 후 우선 시전 |
| 마지막 일반 카드 중 준비 | 집중 이탈 없이 필살 처리 |
| 이동/회복 중 준비 | 실제 해제 후 판단, 중복 대기 없음 |
| N 초과 또는 예약 판단 누락 | 같은 방문 재예약 없음 |
| 한 카드 지연 | 실제 1회만 선행, 취소 인정/생략 미인정 |
| 필살 사용·취소 | 원래 일반 카드 누락·중복 없음 |
| 조우 필살 | 지정 위치와 조우 1회 유지 |
| backAllowed만 다른 quota 입력 | 동일 준비 이동 조건에서 행동 시간열 동일 |
| 입력만 존재하는 대기 | 정확히 입력 원인으로 귀속 |
| 모션/피격/예약 경계 중첩 | 우선순위와 합계 수작업 기대값 일치 |
| 구간 동일 상태 분할 | 행동과 장부 불변 |
| 로그 켜기/끄기 | 난수·피해·쿨비 동일 |

제품과 같은 명시적 카드 입력으로 검증한다. 스킬 단독 테스트를 쓸 때 실제 실행 분기와 시전 횟수를 확인한다. 테스트 시간/쿨은 경계를 수작업 계산할 수 있게 정한다. 특히 단순히 첫 집중에서 준비된 필살을 먼저 쓰는 테스트만으로 '쿨 대기 도중 우선 실행'을 증명하지 않는다.

## 9. 비교와 해석

1. 각 단계 전용 fixture로 실패→수정을 확인한다.
2. 실제 입력으로 600초·100%·N=7.5·500회 수정 전후 비교.
3. 같은 입력 기반으로 660초·100/90/85/80% 각각500회 비교.
4. 회차별 다른 seed/bossSeed, 변경 전후 같은 manifest를 사용한다. 고정 보스 하나의 500회 반복을 다양한 전투 평균으로 보고하지 않는다.

결과는 스킬별 사용·적중·취소·쿨비·미사용 합계, 필살 사용당 대기, 원인별 합계, 우선 판단 위반 건수, 대표 에피소드 3~5개로 제시한다. 실제 피해 입력 없으면 총피해 비교를 제외한다. 카드 버프·면역·공속 보정이 빠진 자료는 실제 입력 검증이 아니다.

전후 평균뿐 아니라 회차별 차이의 평균과 변동 폭을 보고한다. 이동 난수 호출 수 변경이 후속 사건에 영향을 준다면 직접 제거한 지연과 후속 실행 변화가 섞였음을 설명한다.

사용자 관측 85% 필살84%/일반73%는 참고값이다. 100%에서 반드시 10%p 차이를 요구하지 않는다. 오류 제거 후에도 차이가 작다면 정상 난무/예약 대기와 일반 사용당 지연을 근거로 후속 행동 모델 과제를 제안한다. 추가 상수를 이번에 임의 적용하지 않는다.

## 10. 완료 및 인수인계

- 타입 검사와 관련 테스트, 전체 회귀를 적절히 실행한다.
- UI 변경 시 check:ui와 실제 브라우저 DOM 검사; 폭·활성 탭·표시된 결과를 기록한다.
- docs/combat-simulation-rebuild.md와 본 문서에 단계별 변경 파일/입력/기대/실제/남은 작업을 갱신한다.
- 실제 입력 또는 수정 전 기준이 없으면 '미확보'로 명시한다. 추정 입력이나 재구성 코드를 실제 이전 버전으로 표시하지 않는다.
- 완료 보고에는 엔진 변경, 진단만 추가된 부분, 실제 비교 완료 여부를 구분한다. 테스트 추가만으로 동작 개선을 주장하지 않는다.

실행 시작 요청: 이 문서와 AGENTS.md를 읽고 단계 A부터 수행한다. 핵심 테스트가 통과하면 B~D와 비교까지 계속 진행한다. 규칙 충돌이 생기면 해당 부분만 질문하고 독립 작업은 계속한다. 배포하지 않는다.

## 11. 진행 기록

### 단계 A/B/D 1차 검증 — 2026-09-28

- 변경 파일: `src/domain/simulation/combat-simulation.ts`, `tests/unit/combat-simulation.test.ts`.
- 재현한 문제: 정상 시전 경로와 타격 전 취소 경로에서 `addIdle()`이 입력·모션 손실을 기록하기 전에 실행되어, 준비 후 미사용 원인이 이전 상태로 분류될 수 있었다.
- 수정: 두 경로 모두 입력 및 실제 시전 구간을 먼저 기록한 뒤 ready-idle을 분류하도록 순서를 변경했다. 준비 구간은 손실 interval의 모든 시작·종료 경계를 기준으로 분할하고, 겹친 원인은 하나의 우선순위로만 귀속한다.
- 수정하지 않은 것: 실력 상수, 예약 N초, 백어택 범위, 피해 산식, 일반 DPS 산식.
- 전용 검증: 일반 카드가 20초 쿨로 대기하는 동안 5초 쿨 필살이 준비되면 필살이 20초까지 기다리지 않고 5.95초에 실행되는 fixture를 추가했다.
- 검증 결과: 전용 테스트 통과. 기존 단위 테스트 50개 통과. 타입 검사는 테스트 fixture의 필수 `cardId` 누락을 함께 수정한 뒤 재실행한다.
- 남은 단계: 실제 현재 세팅 입력 manifest 보존, 사용 건별 대표 진단, 순수 필살 판단 함수로의 추가 분리 여부, 600/660초 실제 입력 비교.

### 단계 B 1차 검증 — 2026-09-28

- `SimulationInput.recordDecisionDiagnostics`와 `SimulationResult.finisherDecisionSnapshots`를 추가했다.
- 집중 진입 시 예약 결과와 필살 준비 시 일반 카드 선행/필살 우선 판단을 대표 회차에 기록한다.

### 단계 C 1차 검증 — 2026-09-28
