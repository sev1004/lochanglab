# 전투 시뮬레이션: 행동 시간과 피해 계산 분리 계획

후속 일반 스킬 행동 모델은 [일반 스킬 판단 행동 모델 계획](./regular-skill-behavior-plan.md)을 따른다. 90% 주요 일반 스킬 쿨비 검증 기준은 80~84%이며, 선행 정합성 확인 후 미측정 초기값을 검증한다. 이 링크는 해당 기능 구현 완료를 의미하지 않는다.

## 후속 확정: 메인 기믹 5초 전 우선 판단

사용자 확정에 따라 메인 기믹 첫 진입 5초 전부터 필살 우선 예외를 검토한다. 내부 기믹 단계 전환은 새 기믹 진입으로 취급하지 않는다. 반복 집중에서 쿨이 준비되고 연가심공 기회가 남아 있어야 하며, 실제 입력 지연과 모션을 포함한 타격이 기믹 시작보다 빨라야 한다. 정확히 경계인 경우 이 사전 사용 예외로 선택하지 않는다. 360줄 공격 가능 구간 우선 사용도 연가심공과 구간 종료 전 타격 조건을 검사한다.

검증: 타입 검사, 5초/타격 경계 전용 테스트 및 기존 필살 복귀·일반 쿨 대기·연가심공·360 복귀 선택 회귀 테스트 통과. 실제 캐릭터 반복 비교는 아직 수행하지 않았다. 기본 패턴 ¼ 완화 및 이동 원인 세분화는 이 변경의 완료 항목이 아니다.

작성일: 2026-09-28. 상태: **계획 작성, 이 문서에 따른 엔진 구현은 아직 시작하지 않음**.

## 1. 목적과 변경 범위

목적은 쿨타임 감소가 실제 사용 기회와 전투 피해를 얼마나 늘리는지 설명 가능한 방식으로 비교하는 것이다. 쿨비 또는 필살과 일반 스킬의 쿨비 차이를 목표 숫자로 맞추는 작업이 아니다.

사용자가 승인한 방향은 **언제 무엇을 사용했는지 먼저 계산하고, 그 기록으로 피해를 계산하는 구조**다.

```text
실제 세팅과 원본 사이클 + 보스 일정 + 행동 난수
  → 행동 시뮬레이션 1회
  → 시전·타격·취소·버프·쿨·대기 기록
       ├─ 쿨비 및 대기 원인 집계
       └─ 적중별 백어택 정수 배정 → 치명 판정 → 기존 피해 엔진
  → 회차 결과 → 반복 통계 및 쿨감 전후 비교
```

백어택 또는 치명타 추첨 결과 때문에 다음 시전 시각이 달라지지 않게 한다. 단, 실제 적용 효과 중 치명/적중이 쿨 초기화·자원·공속을 바꾸는 효과가 있는지 먼저 조사한다. 이런 효과가 있으면 행동에 필요한 발동 판정만 행동 계층에 남기고, 의존성을 명시한다. 확인 없이 모든 효과를 사후 계산으로 옮기지 않는다.

### 변경하지 않을 것

- 원본 조우·반복 순서, 스탠스 제약, 필살 예약 N초와 판단 실수 공식.
- 합의한 모션·입력 지연·피격 확률 및 시간.
- 사용자 지정 정수 백어택 범위와 기존 정밀 피해 산식.
- 쿨비 정의: `1 − 준비 후 미사용 시간 / 전체 전투시간`.
- 일반 DPS 계산과 편집 UI. 배포 및 실력 상수 보정도 이번 범위 밖이다.

이번 승인만으로 일반 스킬을 자유 우선순위로 바꾸거나, 이동시간을 없애거나, 청룡진을 상시 적용하지 않는다. 단순화하는 대상은 먼저 **계산 책임과 데이터 흐름**이다.

## 2. 실제 코드에서 확인한 충돌과 수정 방향

| 현재 경로 | 문제 또는 확인 필요 사항 | 새 방향 |
| --- | --- | --- |
| `runCombatSimulation` quota 경로 | 적중 수 확보 후 백 배정을 넣어 전체 엔진을 다시 실행 | 행동 1회, 피해 평가 1회 |
| 내부 시뮬레이션의 치명 추첨 | 행동과 같은 난수 흐름을 소비하는 경로 | 행동·백 배정·치명 난수 분리 |
| `SimulationSkill` | 모션·쿨과 많은 피해 시나리오 필드가 혼합 | 타이밍 정의와 피해 시나리오 정의 분리 |
| `sectionedExecution` | `simulationBuild` 누락 시 제품과 다른 경로 실행 가능 | 제품 입력과 가상 시험 입력을 명시적으로 구분 |
| 예약 필살 로그 | 현재 일반 카드 ID와 예약 삽입 시전의 정체성 혼동 가능 | `castId`, 출처, 복귀 카드 ID 분리 |
| 취소 처리 | 실제 취소 시각과 상태이상 회복 시각 혼동 가능 | 취소·모션 해제·회복 시각 별도 기록 |
| 필살 판단 helper | 공격 제한·연가심공·지연 조건 일부가 외부에 흩어짐 | 실제 실행 조건을 받는 단일 판단 계약 |
| 미사용 장부 | 지나간 구간을 현재 상태로 분류하거나 불완전한 기록에 의존 | 상태 구간 기록 후 경계별 합집합/차집합 집계 |
| 반복 실행 | 회차마다 자세한 로그 보관, UI 스레드 장시간 점유 가능 | 필수 경량 기록과 선택 상세 로그 분리, 증분 집계 |

백 배정의 `chooseBackAttackIndices`에 동일 키의 `deterministicRoll`을 매번 반환하는 콜백이 전달되는 경로도 점검한다. 후보 성공 횟수의 균등 추첨과 적중 사건의 균등 부분집합 선택은 별개다. 부분집합 추첨에는 진행하는 독립 난수 스트림 또는 draw index를 사용한다.

### 이전 검증 결과의 정정

제품 입력의 `simulationBuild`, 정확한 공속 보정, 실제 피해 시나리오가 빠진 가상 실행을 현재 캐릭터 결과로 취급하지 않는다. 특히 앞선 약 20% 필살 쿨비 사례는 제품 경로 재현 근거로 사용하지 않는다.

기존 A/B/C/D 단계 완료 보고와 테스트 통과는 새 구조의 완료 근거가 아니다. 기존 테스트는 보존하되 실제로 입증하는 범위를 기록한다.

## 3. 입력 및 실행 기록 계약

파일명은 프로젝트 구조에 맞게 조정하되 다음 책임을 구분한다.

| 구성 요소 | 책임 |
| --- | --- |
| 제품 입력 어댑터 | 페이지의 정확한 세팅·구간·쿨·공속·N초를 검증하여 전달 |
| 행동 엔진 | 보스 사건, 스탠스, 예약, 모션, 이동, 입력, 피격 처리 |
| 행동 기록 | 시전 및 결과, 버프/제한 구간의 단일 사실 원천 |
| 피해 평가기 | 정수 백 배정, 해당 타격 조건의 기존 피해 시나리오 선택, 치명 판정 |
| 쿨 장부 | 쿨 진행 및 준비 후 미사용 구간, 원인 집계 |
| 반복 실행기 | 회차 manifest, 재현, 통계, 선택 로그, 진행 상태 |

### 필수 기록

각 시전에 고유 `castId`를 부여한다. 일반 카드에는 원본 `cardId`를 보존하고 예약 필살에는 일반 카드 ID를 대신 붙이지 않는다.

```ts
type CastOrigin = "encounter" | "repeat-card" | "reserved-finisher";
type HitOutcome = "hit" | "miss" | "cancelled" | "outside-fight";

// 실제 타입은 기존 도메인 타입을 재사용한다.
type CastRecord = {
  castId: string;
  skillId: string;
  cardId?: string;
  resumeCardId?: string;
  origin: CastOrigin;
  visitId: string;
  castStartedAt: number;
  cooldownReadyAt: number;
  plannedImpactAt: number;
  interruptedAt?: number;
  outcome: HitOutcome;
  damageScenarioRef: string;
  // 실제 타격 당시의 버프 및 보스 배율을 보존한다.
  azureActiveAtImpact: boolean;
  yeongaConsumedByCast: boolean;
  bossDamageMultiplierAtImpact?: number;
};
```

- 피해가 0인 기믹 적중은 `hit`이며, 취소/미적중과 다르다.
- 상태이상 회복 시각은 별도 상태 구간에 저장한다. 회복까지를 스킬 모션으로 기록하지 않는다.
- 동일 스킬의 반복 카드도 카드별 시나리오 참조를 유지한다. 공유 쿨은 스킬 ID로 관리한다.
- 필수 기록은 `recordActions`와 무관하게 생성한다. 옵션은 상세 설명 로그 보관 여부만 바꾼다.
- 누락된 필살 계산 데이터를 피해 0 또는 임의 쿨로 대체하지 않고 입력 오류를 반환한다.
- 예약 필살은 독립 스킬 정의로 전달한다. 실행 목록에 가짜 카드를 삽입하지 않는다.

## 4. 행동 엔진이 유지해야 할 규칙

### 사이클·예약

- 조우 선택 1회 → 반복 난무 → 반복 집중. 360줄 종료 후 반복 난무 첫 카드로 복귀한다.
- 최초 난무 최소 1회, 이후 서로 다른 난무 2개, 집중 최소 3회. 최소 횟수는 전환 자격이지 남은 준비 카드를 버리는 조건이 아니다.
- 원본 순서 대기 및 확정된 사두/굉열파 생략만 허용한다. 생략은 사용으로 세지 않는다.
- 집중 전환 **완료** 시 `C <= N` 예약, 초과 시 해당 방문 보류. N과 실수 확률은 변경하지 않는다.
- 예약 필살이 준비되면 일반 쿨 대기 중에도 재평가한다. 이미 시작한 모션은 끊지 않는다.
- 필살 사용/취소 후 다음 미사용 일반 카드로 복귀한다. 예약 필살을 남겨둔 채 집중을 종료하지 않는다.
- 조우 필살은 원본 위치에서 실행한다. 조우를 반복 예약 정책으로 재배치하지 않는다.

### 모션·버프

- 공속 130% 기준 모션: 청룡진 0.55, 맹룡 0.90, 반월 0.70, 사두 0.65, 적룡포 **0.85**, 유성 1.25, 굉열 **1.10**, 필살 1.30초.
- 모션은 `기준 × 130 / 실제 적용 공속`이라는 기존 모델 가정을 유지한다. 입력 지연은 공속 보정하지 않는다.
- 100% 연계 입력 0.05초 예외, 패턴 변경 0.3초. 다른 수준의 기존 공식 유지.
- 청룡진은 자체 쿨과 맹룡 잔여 1초 조건을 만족한 뒤 입력한다. 버프는 시전 시작부터 6초, 정확히 만료 시각의 타격도 적용한다.
- 연가심공은 실제 다음 시전에 소모하며 취소해도 환불하지 않는다. 최초 난무 미사용 및 방문별 기회 규칙을 유지한다.
- 쿨은 시전 시작, 합산 타격은 모션 종료. 피격 취소와 정상 시전 후 미적중을 구분한다.

### 시간·기믹

- 보스 일정을 사전 생성하고 플레이어 행동 때문에 밀지 않는다.
- 동시각: 보스 상태 변경 → 예정 타격 → 상태이상 → 행동 완료/다음 판단.
- 행동 시작은 전투 종료 전만 허용하고, 정확히 종료 시각의 예정 타격 포함 여부는 기존 동작을 확인하여 명시적으로 고정한다. 종료 이후 타격은 제외한다.
- 최신 합의상 이동 불가능 패턴은 없다. 공격 불가와 이동 불가를 혼동하지 않는다.
- 360줄 최초 30초 스킬 사용 구간, 이후 차단 및 60/80초 길이를 유지한다.
- 320줄 최초 30초는 사용·적중 가능하지만 피해 0, 이후 20~30초 피해 50%, 그로기 10초, 공격 불가 5초를 유지한다.
- quota 경로에는 과거 기믹 강제 백/물리 백 금지를 중복 적용하지 않는다. 이동 준비 시간 자체는 별도로 보존한다.
- 상태이상 우선순위·6종 경직 면역·기상기 실제 사용부터 26초·중첩 시간 합집합을 유지한다.

## 5. 피해 평가: 전투 기록을 다시 실행하지 않는다

1. 행동 기록에서 스킬별 유효 적중 사건을 모은다.
2. 해당 수준·스킬의 기존 확정 범위로 정수 성공 횟수 후보를 만든다.
3. 후보 성공 횟수를 동일 확률로 선택한다.
4. 해당 수만큼 적중 사건을 중복 없이 무작위 선택하여 백으로 지정한다.
5. 각 사건의 청룡진·연가심공·백/비백 조건으로 기존 엔진 시나리오를 선택한다.
6. 그 시나리오의 치확과 비치명/치명 피해로 판정하고 보스 피해 배율을 적용한다.

후보는 `ceil(적중수 × 하한) ... floor(적중수 × 상한)`이다. 후보가 없으면 범위에 가장 가까운 성공 횟수로 처리한다. 동률 처리와 0적중 표시는 기존 구현을 확인해 전용 테스트로 고정한다. 0적중은 비율을 0% 성공처럼 해석하지 않도록 N/A로 구분한다.

뭉툭한 가시 등 비선형 조건 때문에 **평균 백 비율을 먼저 능력치에 넣어 한 번 계산하지 않는다**. 각 타격의 상세 조건별 계산 결과를 사용한다. 섬광구슬 등 이미 평균 처리된 효과를 또 추첨하거나 중복 곱하지 않는다.

치명타는 우선 기존 실제 추첨 방식을 유지한다. 비교용 기대 피해 `비치명×(1-p)+치명×p`는 선택적 후속 기능이며, 추가 시 기대 치명 횟수와 실제 횟수를 구분한다. 이번 구조 분리 승인만으로 기본 표시를 기대값으로 변경하지 않는다.

## 6. 쿨비와 대기 장부

쿨 진행 중은 준비 후 미사용이 아니다. 초기 준비 상태의 대기, 기믹 중 쿨 완료 후 대기, 종료 직전 준비 상태의 대기는 포함한다.

일정한 쿨 C의 독립 검산:

```text
각 실제 시전 s에 대해 [s, min(s+C, T)) 구간 생성
전투 [0,T) 내 쿨 진행 구간의 합집합 길이 = B
준비 후 미사용 = T-B
쿨비 = B/T = 1-(T-B)/T
```

이 식은 중도 쿨 변경·초기화가 없는 경우의 검산이다. 그런 효과가 있다면 실제 쿨 상태 전이를 사용한다. 쿨 이전 재사용을 합집합 계산으로 숨기지 말고 별도로 실패시킨다.

원인 집계는 기록된 상태 구간과 준비 구간을 나누어 수행한다. 우선순위를 문서와 코드에 하나로 정의한다. 예: 공격 불가 → 피격 → 스탠스 제한 → 해당 방문 예약 보류 → 이동 → 다른 모션 → 판단/입력 → 순서 대기. 이는 회계상 귀속이며 독립 인과 기여도가 아니다.

필살의 다른 모션은 다음을 구분한다.

- 필살 준비 전에 시작하여 남은 모션.
- 준비 후 사용자 정책상 반드시 먼저 처리한 일반 카드.
- 준비 후 우선 판단 누락으로 발생한 불필요 대기.
- 실제 스탠스 전환 시간.

각 스킬 원인 합계는 그 스킬의 준비 후 미사용 시간과 일치해야 한다. 서로 다른 스킬의 미사용 시간을 더해 플레이어 전체 손실이라고 표시하지 않는다.

40초 중단 시작 시 잔여 쿨이 각각 10초/30초이면, 해당 구간의 미사용은 30초/10초다. 반면 총 미사용 시간이 둘 다 10초라면 같은 전투시간에서 쿨비 손실도 같다. **잔여 쿨과 중단의 실제 배치가 핵심**이므로 쿨이 길다는 이유만으로 고정 가산하지 않는다.

## 7. 난수·반복 실행·성능

- 회차마다 새 보스 상황을 생성하되 manifest를 저장하면 재현할 수 있게 한다.
- 보스, 행동 사건, 백 성공 횟수, 백 사건 배분, 치명 판정을 분리한다.
- 키는 회차·방문/사건·판단 종류로 구성한다. 루프 재진입과 로그 출력이 추첨 횟수를 바꾸지 않게 한다.
- 쿨감 A/B 비교에는 같은 manifest를 사용한다. 쿨감 때문에 시전 수가 달라져도 다음 보스 패턴은 동일해야 한다.
- 행동 2회 실행 제거 전후에 시간/메모리를 측정한다. 회차 결과는 증분 집계하고 상세 로그는 지정 회차만 보관한다.
- 브라우저가 장시간 응답하지 않으면 Worker 또는 취소 가능한 분할 실행으로 분리한다. 진행률은 실제 완료 회차를 사용한다. 이 UI 변경을 할 때만 UI 지침·DOM 검증을 수행한다.

## 8. 단계별 구현과 통과 기준

### A. 실제 기준 입력과 실패 사례 확보

- 제품 `executeCombatSimulation` 입력 생성 경로를 추출한다.
- build, 정확한 쿨/공속, 조우·반복 카드, 피해 시나리오, N초, 수준, 전투시간, 코드 버전을 비밀정보 없이 기록한다.
- 600초·100%와 660초·수준별 500회에 쓸 manifest를 확보한다.
- 기존 오류 의심 사례를 독립 재현한다. 실제 세팅을 확보하지 못하면 가상 검증이라고 명시한다.

**통과:** 페이지와 검증 스크립트가 같은 제품 입력 어댑터를 사용하며 숨은 기본값 차이가 없다.

### B. 행동 기록 및 독립 RNG 도입

- 필수 기록 타입, 출처/ID, 실제 취소 시각, 버프/제한 구간을 추가한다.
- 행동과 피해 난수를 분리한다. 기존 결합 난수 수정으로 개별 결과가 달라지면 원인과 경로를 설명한다. 이전 숫자와의 비트 단위 일치를 억지로 요구하지 않는다.
- 기존 정책을 보존한 행동 전용 실행을 만든다.

**통과:** 치확·피해량·백 범위만 바꾸어도 행동 기록, 쿨비, 보스 일정이 동일하다. 단, 사전 감사에서 확인된 행동 발동 효과는 별도 시험한다.

### C. 사후 피해 평가와 단일 실행 연결

- 정수 quota 및 사건 배분을 행동 기록에 적용한다.
- 기존 피해 시나리오별 판정과 일치시키고 두 번째 전투 실행을 제거한다.
- 제품 결과 타입은 어댑터로 유지하거나 영향 UI를 명시적으로 수정한다.

**통과:** 취소 피해 0, 기믹 적중 피해 0, 청룡진 만료 경계, 백/비백 뭉가·치확, 연가 소모, 로그 유무 독립 및 quota 후보 규칙을 검증한다.

### D. 쿨비·원인 장부 독립화

- 행동 기록에서 쿨 상태와 미사용 구간을 재구성한다.
- 장부를 사건 경계 단위로 집계하고 기존 화면과 연결한다.

**통과:** 원인 합계=미사용 시간, 독립 쿨 구간 검산=엔진 쿨비. 초기·종료·40초 중단·취소·쿨 경계·360 복귀 사례가 모두 일치한다.

### E. 제품 반복 실행 및 쿨감 민감도 비교

- 먼저 기믹 없는 고정 조건, 다음 결정적 기믹, 마지막 실제 보스 일정 순서로 검사한다.
- 실제 세팅 600초·100%와 660초·각 선택 수준 500회 이상 검증한다.
- 쿨감 변경은 다른 능력치를 고정한 민감도 시험과 실제 장비 교체 시험을 분리한다.
- 총피해/DPS, 사용·적중·취소, 쿨비, 필살 대기 원인, 버프 적용률, A/B 회차별 피해 차이와 분산을 보고한다.

**통과:** 쿨감의 결과가 시전 기록으로 설명되고, 강제 기믹·순서 병목과 신규 사용 기회를 구분할 수 있다. 목표 쿨비 달성은 완료 조건이 아니다.

쿨감 후 사용 수가 같으면 쿨비는 오히려 낮아질 수 있다. 개별 회차의 피해 증가도 무조건 보장하지 않는다. 평균과 회차별 차이를 함께 보고 원인을 확인한다.

## 9. 필수 회귀 테스트

- 조우 1회, 반복 방문 교대, 카드 누락/중복 없음, 동일 스킬 공유 쿨.
- 필살 예약 N초 경계·예약 누락·한 스킬 지연·일반 대기 중 필살 우선 판단.
- 스탠스 최소 자격과 준비 카드 처리, 사두/굉열파 생략 경계.
- 입력·모션·피격 시간 중복 없음, 시간 역행 및 조기 재사용 없음.
- 보스 경계 분할만 바꿔도 행동 결과 불변.
- 타격/넘어짐 동시각, 청룡진 만료 시각, 종료 이후 타격 제외.
- 행동 기록을 고정하고 피해 설정만 바꾸는 격리 시험.
- 백 정수 후보 균등 선택 및 부분집합 배분의 결정적 재현/통계 시험.
- 로그 활성 여부와 결과 일치, 단일 회차 합산과 배치 평균 일치.
- 제품 명시 구간 입력과 가상 입력 경로 혼동 차단.

기존 실패 검사를 삭제하거나 허용오차를 넓혀 통과시키지 않는다. 최신 합의와 충돌하는 테스트는 근거를 기록하고 교체한다.

## 10. 다음 단계로 보류할 결정

- 실제 이동을 더 단순한 통합 행동시간 모델로 바꾸는 것은 별도 보정 작업이다. 기존 대기와 이중으로 적용하지 않는다.
- 기대 치명 모드의 기본 사용 여부와 UI 표시는 후속 선택 사항이다.
- 기믹 직전 무조건 필살 사용은 자동 추가하지 않는다. 사전 인지 범위·스탠스·예약·연가심공 제약을 먼저 확정해야 한다.
- 백 범위, 실력별 상수, 85% 관측 쿨비에 맞춘 조정은 이 구조의 정확성이 검증된 이후에만 다룬다.

## 11. 진행 기록과 완료 보고

각 단계마다 변경 파일, 재현 입력, 기대값, 실제 결과, 남은 오류 및 다음 작업을 기록한다. 실제 제품 입력 미확보, 브라우저 미검증, 미측정 모션/행동 가정은 완료 항목과 분리한다.

현재 기록:

- 계획 작성 완료.
- 기존 주요 실행·입력·quota·집계 경로 대조 완료. 기존 단위 테스트 54개를 실행해 모두 통과했으나, 이는 새 구조의 완료를 의미하지 않는다.
- A 일부 완료: 제품 `executeCombatSimulation`의 `simulationBuild`, 공속 보정 모션, N초, 원본 cycle 전달 경로를 확인했다. 실제 캐릭터 입력 manifest 파일은 아직 확보하지 못했다.
- B 일부 완료: quota 실행 시 행동 추적 pass가 항상 시전 기록을 만들도록 바꾸고, 시드가 있는 batch의 회차별 seed를 결정적으로 분리했다. 시전 기록에 `castId`를 추가했으며 quota hit 배정은 진행하는 RNG stream을 사용한다.
- C 부분 완료: 행동 기록에 적중 순번·청룡진 활성·연가심공 적용 상태를 저장하고, 해당 기록을 순회하는 `resolveQuotaDamageFromActions`를 연결했다. quota 피해 계산은 이제 보스 시간축·커서·이동을 재실행하지 않는다.
- C 남은 부분: quota가 아닌 물리 모델의 순수 피해 resolver 통합, 시나리오 선택 함수 중복 제거, 취소·기믹 0피해·치명 경계에 대한 전용 격리 테스트가 남아 있다.
- 쿨비 장부의 최종 구간 sweep, 실제 제품 manifest 기반 600초/660초 비교, A/B 쿨감 검증은 미착수다.
- 다음 작업은 **C: 행동 기록을 입력으로 받는 순수 피해 평가기 작성 및 두 번째 시간 진행 제거**다.

완료 보고는 구현 완료 / 실제 검증 완료 / 모델 가정 / 관측값 차이 / 남은 작업으로 나눈다. 이전 완료 표현을 새 구조의 검증 결과로 재사용하지 않는다.
