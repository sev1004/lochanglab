# 적룡필살 준비·대기 오류 수정 실행 계획

작성: 2026-09-28. 상태: 단계 B·C 1차 수정 완료, 단계 D·E 진행 중.

## 1. 목적과 범위

정수 백어택 배정(quota)으로 전환한 뒤 남아 있는 물리 백 조건, 준비 후 미사용 장부, 한 일반 스킬 지연 상태를 수정한다. 수정 전후 동일 전투를 비교해 필살과 일반 스킬 쿨비 차이에 미친 영향을 확인한다.

백어택 확정 범위, 피해 산식, 사용자 예약 N초, 실력 확률·행동 상수, 기믹 시간은 유지한다. 쿨비 10%p 차이를 강제로 만들지 않는다. 일반 DPS·편집 UI 재설계·배포는 범위 밖이다.

구현 시작 전 AGENTS.md, combat-simulation-rebuild.md, simulation-back-attack-quota-plan.md를 읽는다. 관련 과거 완료 기록보다 이 문서의 재현 사실과 최신 사용자 합의를 우선한다. 기존 변경사항을 보존한다.

## 2. 확인한 사실과 아직 확인하지 못한 영향

### 재현된 이동 오류

combat-simulation.ts의 필살 이동 완료 판정은 아직 afterMove.backAllowed를 요구한다. quota에서도 백 금지 구간이면 이동이 끝나도 playerAtBack을 갱신하지 못하고 다시 이동한다. 준비 확인 지연 추첨도 window.backAllowed && playerAtBack에 묶여 있다.

가상 재현: seed=52, 20초, 수준100, quota, 일반 스킬 쿨3초/모션1초, 필살 쿨5초/모션1초. 공격 가능한 단일 구간, directionVersion=1, 위험 사건 없음. backAllowed만 변경했다.

| backAllowed | 일반 사용 | 필살 사용 | 이동 기록 |
|---|---:|---:|---:|
| true | 6 | 4 | 1 |
| false | 0 | 0 | 10 |

이것은 경로 오류 재현용 가상 입력이다. 실제 캐릭터에서 몇 초 손실인지 증명하지 않는다.

### 코드에서 확인한 추가 문제

- 정상 시전 경로가 addIdle을 호출한 뒤 현재 입력 구간을 recordLoss로 등록한다. 방금 발생한 입력 대기를 분류 시점에 볼 수 없다.
- 취소 경로의 입력·중단 전 모션 기록도 정상 경로와 대조해야 한다.
- 한 카드 지연을 실제 시전 전에 소모한다. 다음 카드가 쿨이면 대기 후 필살을 먼저 선택할 수 있다.
- lossIntervals.find는 중첩 원인을 명시적 우선순위가 아닌 삽입 순서로 선택한다. 관련 구간의 시작·종료 경계를 모두 순회하는지도 재검증해야 한다.
- 기존 신규 필살 단독 테스트는 일반 카드가 없어 실행 루프 자체를 돌지 않는다. 기존 물리/quota 비교 테스트에는 필살이 없다. 두 테스트 통과는 필살 경로 검증이 아니다.

기존 '백 금지 제거 완료'는 집계 조건 일부만 변경한 상태였다. 물리/quota 비교는 수정 전/후 비교도 아니므로 완료 증거로 사용하지 않는다.

## 3. 단계 A: 변경 전 입력과 실패 재현 보존

주요 파일: src/domain/simulation/combat-simulation.ts, tests/unit/combat-simulation.test.ts. 필요하면 전용 진단 테스트/스크립트를 추가한다.

1. 현재 작업 트리의 관련 엔진 의존 파일을 기준 버전으로 보존한다. HEAD가 미커밋 변경을 포함한다고 가정하지 않는다. 파일 해시·입력·시드를 기록하고 사용자 파일을 덮어쓰지 않는다.
2. 위 20초 재현을 전용 테스트로 만든다. 양쪽 모두 일반/필살의 실제 시전을 확인한 뒤, quota에서 backAllowed만 바꾸면 시전 시간열·이동 완료·쿨비가 동일해야 한다는 기대를 둔다.
3. 제품 경로인 simulationBuild=jeoljeong-non222와 명시적 조우/반복 카드 입력에서도 재현한다. 조우 유무, 예약 필살, 일반 카드 쿨 대기, 일반 카드 소진을 포함한다.
4. 입력 분류와 한 카드 지연을 각각 작은 고정 시간축으로 재현한다. 테스트가 실제 대상 분기를 실행했음을 시전/방문/카드 기록으로 확인한다.

완료 조건: 수정 전 실패가 확인되고, 실패 이유와 기대값을 기록한다. 기존 의미 없는 테스트는 요구사항을 직접 증명하는 검사로 강화하며 변경 이유를 남긴다.

## 4. 단계 B: 준비 이동 완료와 백어택 성공 분리

- 준비 위치 도달 상태와 타격 백어택 여부를 별도 개념으로 취급한다. quota에서 준비 완료는 이동 잔여량 0, 중단 없음, 목표 방향 유효 여부로 결정한다.
- quota 준비 완료에 backAllowed 또는 attackable을 요구하지 않는다. 공격 불가 중에도 이동은 가능하다는 합의를 지킨다. 시전 가능 여부는 별도로 실제 공격 가능·스킬 제한을 검사한다.
- 물리 모델을 유지한다면 물리 백 조건은 해당 모델에만 적용한다. quota 경로와 함께 쓰는 완료 판정을 하나의 함수로 모아 필살 직전/선제 이동/기믹 중 이동/패턴 사이 이동의 누락을 방지한다.
- 이동을 완료하면 상태에 반영하고, 동일 목표에 대해 이동시간을 다시 추첨하지 않는다. 보스 방향 변경·피격은 진행 위치/잔여량을 보존하며 기존 규칙에 따라 재평가한다.
- 예약 필살을 선택할 수 있는지 판단하는 조건에서도 잔존 물리 백 조건을 제거한다. 1회 준비 확인 지연 추첨은 준비 행동과 실제 공격 조건을 만족하는 첫 시점에 수행한다.
- 이미 진행 중인 일반 모션을 끊지 않는다. 사용 가능한 예약 필살은 일반 쿨 대기 중 준비 시각에 재판단하며, 사용 후 원래 미사용 일반 카드로 복귀한다.

검증: backAllowed만 다른 quota 전투의 행동 시간열 일치, 이동 실제 시간 유지, 딜 불가 중 준비 가능, 방향 변경/피격/정확한 구간 끝 완료, 완료 후 재과금 없음. 보스의 공격 금지는 그대로 적용된다.

## 5. 단계 C: 실제 시전 1회까지 지연 상태 유지

- 방문별 판단 완료 여부, 지연 대기 카드 ID, 소모 여부를 구분한다.
- 일반 카드의 쿨·입력·3잡·피격 대기로 반복문에 재진입해도 상태와 ID를 보존한다.
- 확정된 사두/굉열파 생략이면 다음 미사용 카드로 옮긴다. 생략은 1회 시전으로 세지 않고 재추첨하지 않는다.
- 일반 카드가 실제 시전 시작하는 순간 한 번만 소모한다. 타격 전 취소도 시전으로 인정한다. 입력 중 피격으로 시전하지 못했다면 미소모다.
- 일반 카드가 모두 소진되면 추가 대기 없이 기존 필살 준비 절차로 간다.
- 조우 필살은 원본 위치에서 실행하며 이 반복 예약 실수의 대상이 아니다.

검증: 일반 카드 쿨 대기/입력 피격/3잡을 거쳐 정확히 1회 먼저 시전, 취소와 생략 구별, 카드 소진, 같은 방문 재추첨 없음, 필살 삽입 후 누락·중복 없음. 확률 검사는 고정 이벤트 시드로 성공/실패 경로를 각각 실행한다.

## 6. 단계 D: 미사용 시간 장부 정정

입력과 실제 모션 구간을 기록한 뒤 해당 사용 직전의 ready-idle을 분류한다. 미래 회복 시간을 현재 입력 시간에 섞지 않는다. 취소 시 실제 중단 시각까지의 모션과 중단 후 상태이상을 따로 기록한다.

각 스킬의 [쿨 완료, 다음 시전 시작) 및 종료 시 남은 준비 구간을 모든 관련 경계에서 분할한다. 초기 준비 시각은 0이다. 보스 구간, 행동 시작/종료, 예약 상태, 스탠스 방문/전환 경계를 포함한다.

중첩 단일 귀속 순서는 다음으로 명시한다: 공격 불가/스킬 제한 → 상태이상 → 난무·스탠스 전환 → 집중 예약 보류 → 물리 모델에서만 백 금지 → 이동 → 다른 스킬 모션 → 패턴 대응 판단 → 입력 → 일반 카드 순서 대기. 이는 설명용 귀속 규칙이며 독립적인 인과 기여도가 아니다.

- 스탠스 이력 없이 과거 대기를 현재 스탠스로 분류하지 않는다.
- 패턴 대응은 순서 대기와 별도 원인으로 기록한다. 필요한 최소 결과 표기만 추가하고 UI 규칙을 따른다.
- 완료한 이동/쿨 진행 중 대기/전투 종료 이후 쿨 구간을 미사용 시간으로 추가하지 않는다.
- 원인별 합계 = 준비 후 미사용 시간. 쿨비 = 1 - 미사용 시간/전투시간.
- 고정 쿨이고 쿨 초기화가 없는 fixture에서는 시전 시작부터 쿨 완료까지의 구간을 전투시간으로 잘라 합집합으로 계산한 값과 독립 대조한다. 사용횟수×쿨타임만으로 대체하지 않는다.

검증: 입력만 0.05초인 준비 대기, 다른 스킬 모션 중 쿨 완료, 상태 중첩, 예약 변경, 난무 복귀, 초기/종료 대기. 구간을 동일 상태로 나눠도 장부가 같아야 한다. 분류만 바꾼 단계에서는 시전·피해·전체 미사용 시간이 변하지 않아야 한다.

## 7. 단계 E: 동일 전투 수정 전후 비교

수정 전/후 모두 quota, 동일 입력·보스 타임라인·전투 시드·N을 사용한다. 물리 모델과 quota 모델 비교로 대체하지 않는다. 이동 호출 감소가 후속 난수 소비를 바꾸는 영향도 기록하며, 가능하면 사건별 비교로 직접 대기 제거와 후속 전투 변화를 구분한다.

1. 고정 20초 및 명시적 구간 fixture에서 수정 효과를 확인한다.
2. 실제 현재 세팅을 자격증명 없이 확보한다. 카드 ID·순서·공속·최종 쿨·모션·N·수준을 저장한다. 필살 쿨33.66초는 사용자 관측이며 현재 입력과 일치하는지 확인한다.
3. 사용자 최신 결과에 맞춘 600초·100%·500회 비교를 먼저 수행한다. 이어 같은 입력으로 660초·100/90/85/80% 각500회 비교한다. 반복 수·시드 목록을 보존한다.
4. 실제 입력이 확보되지 않으면 가상 비교만 기록하고 실제 세팅 검증은 미완료로 남긴다.

보고 표: 필살/일반 스킬별 사용·적중·취소, 쿨비, 준비 후 미사용 총시간과 원인, 총피해, 이동 횟수/시간, 준비 확인 지연 발생/소모 횟수. 대표 필살 3~5회는 쿨 완료→집중 진입/예약→준비 이동 완료→입력→시전 시간을 나열한다.

각 단계별 차이를 따로 기록한다. 원인 분류 정정만으로 쿨비 개선을 주장하지 않는다. 실제 10%p 격차에 못 미치면 남은 정상 예약·스탠스·강제 기믹 대기를 제시하고 이후 행동 모델 조정과 구분한다.

## 8. 실행 및 완료 기준

실패 재현 → B 이동 수정 → C 지연 상태 수정 → D 장부 수정 → E 비교 순서다. 단계별 핵심 테스트가 통과한 후 다음 단계로 진행한다.

- 타입 검사, 시뮬레이션 전용/회귀 테스트를 실행한다. 실패 기대값이나 허용오차를 완화하지 않는다.
- 로그 유무가 시전·피해·쿨비에 영향을 주지 않아야 한다.
- UI를 변경하면 관련 Next.js 로컬 문서와 ui-layout-rules.md를 읽고 check:ui 및 실제 DOM 검사를 수행한다. 검사한 폭·탭을 기록한다.
- 계획/진행 문서의 이전 과도한 완료 표현을 정정한다. 테스트 통과와 실제 세팅 비교 완료를 구분한다.
- 최종 보고에는 변경 파일, 재현 입력, 단계별 전후 수치, 가정, 남은 문제를 남긴다.

현재 상태: quota 준비 이동의 물리 백 조건 분리, 한 카드 지연 소모 시점, 상태이상·모션·패턴 대응 분류를 수정하고 회귀 검증했다. 전체 원인 합계 독립 검산과 실제 현재 세팅 전후 비교는 남아 있다.
