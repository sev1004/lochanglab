# 85% 플레이의 필살·일반 스킬 쿨비 수정 계획

## 목적과 범위

사용자 제공 결과를 토대로 정확성 수정, 진단 장부 검증, 행동 모델 조정 순서로 진행한다. 이번 문서는 구현 지침이며 제품 코드를 변경하지 않았다.

85% 플레이의 관측 목표는 적룡필살 쿨비 약 84%, 적룡포·유성강천·굉열파 약 73%대다. 맹룡열파는 기존 주요 스킬 관측군으로 함께 보고하되 최신 사용자 결과에는 없으므로 측정한다. 청룡진·사두룡격·반월섬에 동일한 목표를 강제하지 않는다.

이번 목표의 수치 허용오차는 미확정이다. 기존 상대 총딜 ±3% 조건을 쿨비 허용오차로 전용하지 않는다. 구현 정확성 검증은 먼저 진행할 수 있으며 목표 도달 선언 전에 허용범위를 확인한다.

## 1. 기준 결과와 해석

사용자 실행: 660초, 500회, N=7.5초. 아래는 사용자 제공 UI 결과로, 동일 시드 비교나 보존된 원본 실행 자료가 아니다.

| 수준 | 필살 쿨비 | 적·유·굉 쿨비 |
|---|---:|---:|
|90|84.72%|80.16%|
|85|82.13%|79.80%|
|80|77.54%|76.37%|

85% 필살 준비 후 미사용 원인: 강제 공격 불가 44.81초, 스탠스·순서 38.79초, 예약 보류 11.05초, 백 금지 1.35초, 이동 11.63초, 다른 모션 0.87초, 입력 9.46초. 합계 117.96초는 표시 쿨비로 역산한 117.942초와 반올림 범위에서 일치한다. 이는 원인별 귀속이 정확하다는 증거는 아니다.

목표 84%는 필살 총 미사용 105.6초로 현재보다 약 12.34초 적다. 일반 73%는 스킬별 178.2초로 현재 133.32초보다 44.88초 많다. 이 차이를 상수 대기나 사후 보정으로 넣지 않는다.

이전 브라우저에서 확인한 화면상 필살 쿨 33.66초, 주요 일반 12.13초, 공속 130.19%는 재현 입력을 확보할 때 다시 대조한다. 일반 스킬 지연이 집중 진입을 늦춰 필살에도 영향을 주므로 두 목표는 독립 조절할 수 없다.

## 2. 유지할 규칙

- N=7.5 유지. 집중 진입 완료 시 C<=N이면 예약 판단, 초과면 해당 방문 보류.
- 85% 예약 누락 9%, 한 일반 스킬 지연 4.5% 유지. 90·100% 두 확률은 0%.
- 조우 1회, 원본 반복 난무·집중 순서, 공유 쿨, 최소 전환 조건, 확정된 사두·굉열파 생략 유지.
- 청룡진·연가심공·시전 취소·경직 면역·기상기 규칙 유지.
- 보스 시간축, 기믹 지속시간과 공격 허용 구간 유지. 320줄 첫 30초는 사용 가능/피해 0이라는 최신 규칙 유지.
- 일반 스킬 모션을 끊지 않는다. 합의된 허용 시점에서만 이동한다.
- 쿨비는 전투 전체 시간 기준 준비 후 미사용 구간으로 계산한다. 취소 시전도 실제 쿨 사용으로 처리한다.
- 직접 피해 배율, 백 실패 확률, 강제 카드 누락, 결과 순위 정렬로 목표에 맞추지 않는다.

## 3. 작업 A — 실제 입력과 수정 전 기준 확보

대상: page.tsx의 executeCombatSimulation, 검증 스크립트/fixture.

1. 현재 엔진 전달 입력을 재현 가능한 자료로 보존한다. 스킬별 최종 쿨·모션·피해 시나리오, 조우/반복 카드 ID·순서, 공속, 수준, N을 포함한다. API 키·인증 정보는 제외한다.
2. 모든 실행 스킬과 별도 필살 정의의 쿨·피해 데이터에 누락/NaN/Infinity 검사를 적용한다. 누락을 0초/10초로 실행하지 않는다. 합법적인 0초 단위 테스트와 제품 데이터 검사를 구분한다.
3. 정상적으로 로드된 실제 입력과 가상 입력을 문서에서 구분한다. 실제 입력이 없으면 통계 결과를 실제 캐릭터 결과로 보고하지 않는다.
4. 660초·85%·500회 실행 원본과 시드를 보존한다. 변경 전후 진단에서는 같은 시드를 재사용하고 일반 실행은 매번 다른 상황을 유지한다.

완료: 제품 실행 입력으로 재실행이 가능하고 독립 쿨비 검산과 엔진 값이 일치한다.

## 4. 작업 B — 기존 수정의 누락 보완

대상: combat-simulation.ts, behavior-profile.ts, combat-simulation.test.ts.

### B1. 판단 난수 영향 범위

현재 공용 deterministicRoll은 예약뿐 아니라 방향 인지와 3잡에도 사용된다. 이전 혼합 방식 변경은 이 사건들의 결과도 바꿨다. 판단 전용 함수를 분리하고 난수 버전을 기록한다. 기존 결과와 비교할 때 이 변경을 누락하지 않는다.

확률표, 사건별 재현성, 인접 방문 연속 누락 빈도, 로그 활성화 독립성을 검사한다. 새 함수의 통계 검증은 사전에 정한 고정 표본과 통계 기준을 사용하고 실패 후 허용오차를 늘리지 않는다.

### B2. 한 스킬 지연

현재 지연 플래그가 일반 카드 쿨/입력 대기 전에 소모되는 경로가 남아 있다. 방문 상태를 판단 전/지연 카드 대기/시전 완료/필살 처리 완료로 구분한다.

- 지연 대상 카드 ID를 보존하고 실제 시전 시작 때만 소모한다.
- 쿨 대기, 입력 중 피격, 3잡 대응, 내부 구간 경계는 소비·재추첨을 유발하지 않는다.
- 조건부 생략은 다음 미사용 카드로 이관한다. 모두 생략되면 필살 준비 절차로 진행한다.
- 실제 시전 후 취소는 1회 사용으로 인정한다.
- 필살 진단의 카드 ID는 다음 일반 카드 ID를 재사용하지 않는다.

### B3. 이동

잔여 이동시간 0 확인뿐 아니라 방향 유효성, 경계에서 정확히 완료, 이동 목적 변경, 피격 후 남은 이동 보존을 함께 검증한다. 일부 분기의 무조건 playerAtBack=true 처리와 정확한 window.end에서 완료가 누락되는 경로를 확인한다.

완료: 각각 실패 재현→수정→전용 회귀 테스트 통과. 기존 105개 테스트 통과만으로 완료 처리하지 않는다.

## 5. 작업 C — 모든 스킬 미사용 장부

대상: 엔진 진단 타입, 집계 함수, 필요한 최소 결과 UI.

현재 예약 구간은 스탠스 진입 때 닫히며 방문 내부 상태 변경을 매번 기록하지 않는다. 과거 대기를 현재/마지막 상태로 재분류하지 않도록 모든 상태 전이에 시각을 남긴다.

스킬별 준비 구간과 원인 구간을 교차하여 집계한다. 경계는 시작 포함·종료 제외, 초기 준비와 종료 대기 포함, 쿨 진행은 제외한다. 겹치는 구간은 모든 시작/종료 경계로 분할한다.

원인 우선순위:

1. 해당 스킬 공격 불가(강제 기믹/허용 스킬 제한 포함)
2. 피격 행동 제한
3. 다른 스탠스 및 스탠스 전환
4. 필살 예약 정책상 보류 / 판단 누락 보류
5. 필살 백 금지
6. 뒤잡기·추적·회피 이동
7. 다른 스킬 모션 / 앞 카드 순서 대기
8. 공격 재개 판단 / 기회 판단 / 실제 입력

여러 제약이 동시에 걸리는 시간은 위 우선순위로 한 곳에만 귀속한다. 귀속값은 원인 제거 시 얻는 독립 효과가 아니다. 이유 없는 남은 시간은 미분류로 드러내고 정상 시나리오에서 0인지 검증한다.

필살은 정책/판단 보류를 분리하고, 일반 스킬도 동일 장부를 가진다. 전체 플레이어 손실은 별도 합집합이며 스킬별 대기 합계가 아니다. 시전별 쿨 완료→시작 지연과 초기/마지막 대기를 별도 보고한다.

완료: 각 스킬 원인 합계=readyIdleSeconds, 독립 시전 기록 검산 일치, 로그 유무 결과 동일, 예약 상태가 여러 번 바뀌는 예제의 수작업 귀속 일치.

## 6. 작업 D — 필살 선제 준비 연결

작업 B/C 통과 후 실행한다.

- 합의된 쿨 대기·스탠스 전환·대응 구간에서 예약 필살 준비를 평가한다.
- 일반 모션을 중단하거나 카드 순서를 바꾸지 않는다.
- 쿨이 끝나기 전에 완료한 이동·판단을 쿨 완료 후 반복 부과하지 않는다.
- 일반 카드 쿨 대기 중 필살 준비 사건에서 재판단한다. 진행 중 모션은 끝낸다.
- 백 금지 중에는 기존 규칙대로 일반 카드를 처리하고 필살은 보류한다.
- 공개되지 않은 다음 패턴 정보를 쓰지 않는다.

이 단계에서 85%의 필살 대기가 실제로 얼마나 감소하는지 측정한다. 목표 12.34초를 코드에 직접 넣지 않으며, 개선되지 않으면 원인과 제한 조건을 보고한다.

## 7. 작업 E — 일반 공격 판단 모델 조정

정확성 수정 후 기준값을 새로 측정한 뒤 시작한다. 기존 관측값과 오류 수정 후 기준값을 섞지 않는다.

### E1. 공격 재개 판단

보스 공격 불가→가능 또는 실제 대응 종료 사건에만 재개 판단을 부여한다. 매 스킬·반복문마다 부여하지 않는다. 이미 진행한 판단은 피격/경계 후에도 진행도를 보존한다. 판단 후 기존 입력 지연을 적용하며 중복 지연 여부를 검사한다.

### E2. 짧은 공격 기회

공개 근거가 있는 공격 구간에서만 예상 타격 시간과 판단 여유시간으로 사용/대기를 결정한다. 현재 합의는 방향 변경 시점·방향 공개이며 모든 공격 종료 시점 공개가 아니다. 공개 근거가 없는 구간에는 미래 시간축을 제공하지 않고 반응형 재개만 사용한다.

대기해도 카드는 유지한다. 다음 실제 사건에서 같은 카드를 재평가한다. 일반 공격을 멈추는 판단은 안전/물리적 제약인지 판단 지연인지 구분한다. 실제 위험 때문에 멈췄다면 필살도 동일 제약을 받는다. 필살은 합의된 예약 준비 정책에 따라서만 우선한다.

### E3. 프로필 값 선정

- 기존 입력 지연·실수 확률·N은 고정하고 행동 변수 하나씩만 변경한다.
- 현재 프로필의 85% 재개 0.15초와 90% 0.2초처럼 순서가 역전된 값은 다른 항목과 함께 검토한다. 상위가 같은 사건에서 더 느리지 않게 프로필 전 구간을 점검한다.
- 새 행동값은 별도 설정·버전과 미측정 가정 표시를 갖는다.
- 후보 범위는 실제 대기 사건 횟수/지속시간과 현재 프로필을 근거로 정하고 표로 기록한다. 44.88초를 스킬별 횟수로 나눠 강제 지연시키지 않는다.
- 85%만 맞추는 분기를 만들지 않는다. 100/90/85/80/70/60 프로필에 일관된 함수를 적용하고 같은 사건의 판단 조건은 상위가 불리하지 않게 한다.

완료: 일반 스킬 쿨비 변화가 기록된 판단·대기로 설명되고 필살/백어택/취소/총딜의 동반 변화를 보고한다. 목표와 충돌하면 실패한 조합과 이유를 남기고 사후 수정하지 않는다.

## 8. 검증과 실행 순서

A 입력 확보 → B 오류 수정 → C 장부 → D 선제 준비 → E 재개 판단 → 필요 시 E 공격 기회 순서로 진행한다. 단계 핵심 테스트가 통과해야 다음으로 간다.

- 명시적 구간 제품 경로(simulationBuild 포함)로 검증한다.
- 수작업 가능한 보스 고정 구간에서 쿨/이동/상태/판단 경계를 검증한다.
- 실제 입력으로 660초·수준별 500회 이상 실행한다. 수정 전후는 같은 시드 묶음으로 비교한다.
- 보정에 쓰지 않은 별도 시드 500회와 다른 전투시간에서도 확인한다. 일반 실행 독립 난수는 유지한다.
- 평균·표준편차·평균의 신뢰구간, 스킬별 사용·취소·미적중·백어택·쿨비·총피해, 원인별 대기를 보고한다.
- 개별 전투 또는 단일 평균 역전을 즉시 오류로 단정하지 않는다. 반복되는 역전과 원인을 분석한다.
- 같은 타격 조건의 피해는 실력에 따라 달라지지 않아야 한다.
- 상대 총딜 목표와 쿨비 목표의 동시 충족 여부는 별도로 보고한다.
- UI를 변경하면 프로젝트 UI 지침/Next 로컬 문서를 읽고 typecheck, 관련/회귀 테스트, check:ui, 실제 브라우저 DOM 검증을 수행한다. 화면 크기·활성 탭·실제 결과 영역 검사 여부를 기록한다.

## 9. 보고 및 남은 결정

매 단계 계획 문서에 변경 파일, 재현 입력, 기대값·결과, 남은 문제를 갱신한다. 완료 보고는 정확성 수정 완료 / 행동 모델 가정 / 실제 검증 / 목표 미달을 구분한다.

지금은 추가 사용자 답변 없이 A~D 진행이 가능하다. E2에서 추가 공격 구간 정보를 공개해야 하는 경우에는 해당 패턴·정보만 질문한다. 84%·73%대의 수치적 합격범위는 목표 검증 전에 확인한다. 새 규칙을 임의로 확대하지 않는다.

### 2026-09-27 프로필 역전 수정

- 85% 프로필의 공격 재개 지연을 0.15초에서 0.30초로 조정했다. 기존 90%의 0.20초보다 85%가 빠르게 재개하던 역전을 제거했다.
- 85% 뒤잡기 이동 배율을 1.14에서 1.22로 조정했다. 기존 90%의 1.16보다 85%가 짧게 이동하던 역전을 제거했다.
- 80%·70% 프로필의 재개 지연과 이동 배율도 낮은 수준이 더 유리해지지 않도록 단조 순서로 정리했다.
- 프로필 단조성 회귀 테스트를 추가했다.
- 이 값들은 목표 쿨비에 맞춘 직접 보정이 아니라, 명백한 실력 역전 오류를 제거하는 정합성 수정이다.
